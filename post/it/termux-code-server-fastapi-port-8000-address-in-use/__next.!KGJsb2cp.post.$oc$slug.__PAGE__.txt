f:T4178,<h2 id="상황" tabindex="-1" data-src-line="1">상황 <a class="header-anchor" href="#상황" aria-hidden="true">#</a></h2>
<p>Termux 환경에서 FastAPI 또는 Uvicorn 서버를 실행하고 있었다.</p>
<p>예를 들면 다음과 같은 방식이다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">python main.py
</code></pre></div></code></pre>
<p>또는 <code>main.py</code> 내부에서 다음처럼 8000번 포트를 사용하고 있었다.</p>
<pre><code class="language-python"><div class="code-block"><div class="code-header"><span class="code-title">python</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-python"><code class="hljs language-python">uvicorn.run(
    <span class="hljs-string">&quot;main:app&quot;</span>,
    host=<span class="hljs-string">&quot;0.0.0.0&quot;</span>,
    port=<span class="hljs-number">8000</span>,
    reload=<span class="hljs-literal">False</span>,
)
</code></pre></div></code></pre>
<p>그런데 서버를 정상적으로 <code>Ctrl + C</code>로 종료한 것이 아니라, <strong>Code-server 자체를 중간에 꺼버렸다.</strong></p>
<p>그 이후 다시 서버를 실행하면 다음과 같은 오류가 발생한다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">ERROR:    [Errno 98] Address already <span class="hljs-keyword">in</span> use
</code></pre></div></code></pre>
<p>즉, 8000번 포트가 이미 사용 중이라고 나온다.</p>
<hr>
<h2 id="원인" tabindex="-1" data-src-line="34">원인 <a class="header-anchor" href="#원인" aria-hidden="true">#</a></h2>
<p>이 경우 핵심은 다음과 같다.</p>
<p><strong>Code-server 터미널 안에서 실행 중이던 Python/Uvicorn 서버 프로세스가 완전히 종료되지 않고 남아 있을 가능성이 높다.</strong></p>
<p>흐름으로 보면 이렇다.</p>
<pre><code class="language-text"><div class="code-block"><div class="code-header"><span class="code-title">plain</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-plain"><code class="hljs language-plain">Code-server 터미널에서 python main.py 실행
        ↓
FastAPI/Uvicorn 서버가 8000번 포트를 점유
        ↓
Ctrl + C로 정상 종료하지 않고 Code-server를 종료
        ↓
터미널 화면은 사라졌지만 자식 프로세스가 남을 수 있음
        ↓
8000번 포트가 계속 점유됨
        ↓
다시 python main.py 실행 시 Address already in use 발생
</code></pre></div></code></pre>
<p>즉, <strong>포트가 혼자 살아있는 것이 아니라, 8000번을 잡고 있는 프로세스가 어딘가에 남아 있는 상태</strong>다.</p>
<hr>
<h2 id="확인된-단서" tabindex="-1" data-src-line="60">확인된 단서 <a class="header-anchor" href="#확인된-단서" aria-hidden="true">#</a></h2>
<p>프로세스 조회 결과에 이런 항목이 있었다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">u0_a438  26040 ... pts/0 ... /data/data/com.termux/files/home/workspace/my-llm-project/back/venv/bin/python ...
</code></pre></div></code></pre>
<p>여기서 중요한 부분은 <code>pts/0</code>이다.</p>
<p>현재 새로 사용하는 터미널은 <code>pts/1</code>인데, 이전 Code-server 터미널이 <code>pts/0</code>였을 가능성이 있다.</p>
<p>즉, 이전 터미널에 연결되어 있던 프로세스가 남아 있을 수 있다.</p>
<hr>
<h2 id="lsof로-보이지-않는-경우" tabindex="-1" data-src-line="76">lsof로 보이지 않는 경우 <a class="header-anchor" href="#lsof로-보이지-않는-경우" aria-hidden="true">#</a></h2>
<p>보통 포트 점유 프로세스를 찾을 때는 다음 명령을 사용한다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">lsof -nP -iTCP:8000
</code></pre></div></code></pre>
<p>하지만 Termux나 Android 환경에서는 이 명령으로 아무것도 나오지 않을 수 있다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">(venv) ➜  app git:(main) ✗ lsof -nP -iTCP:8000
(venv) ➜  app git:(main) ✗
</code></pre></div></code></pre>
<p>그런데 다시 서버를 실행하면 여전히 다음 오류가 발생한다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">ERROR:    [Errno 98] Address already <span class="hljs-keyword">in</span> use
</code></pre></div></code></pre>
<p>이 경우 <code>lsof</code>에 안 보인다고 해서 포트가 비어 있다고 단정하면 안 된다.</p>
<p>Termux 환경에서는 Android 권한이나 프로세스 소유자 문제 때문에 포트를 잡고 있는 프로세스가 제대로 표시되지 않을 수 있다.</p>
<hr>
<h2 id="1-이전-터미널에-붙어-있던-프로세스-찾기" tabindex="-1" data-src-line="103">1. 이전 터미널에 붙어 있던 프로세스 찾기 <a class="header-anchor" href="#1-이전-터미널에-붙어-있던-프로세스-찾기" aria-hidden="true">#</a></h2>
<p>먼저 <code>pts/0</code>에 붙어 있는 프로세스를 확인한다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">ps -A -o pid,ppid,<span class="hljs-built_in">tty</span>,<span class="hljs-built_in">stat</span>,args | grep <span class="hljs-string">&#x27;pts/0&#x27;</span>
</code></pre></div></code></pre>
<p>만약 위 명령이 Termux에서 잘 안 되면 간단하게 확인한다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">ps -A | grep <span class="hljs-string">&#x27;pts/0&#x27;</span>
</code></pre></div></code></pre>
<p>여기서 나온 PID가 이전 Code-server 터미널에서 남은 프로세스일 수 있다.</p>
<hr>
<h2 id="2-해당-pid-종료하기" tabindex="-1" data-src-line="121">2. 해당 PID 종료하기 <a class="header-anchor" href="#2-해당-pid-종료하기" aria-hidden="true">#</a></h2>
<p>예를 들어 PID가 <code>26040</code>이라면 다음처럼 종료한다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash"><span class="hljs-built_in">kill</span> 26040
</code></pre></div></code></pre>
<p>안 죽으면 강제 종료한다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash"><span class="hljs-built_in">kill</span> -9 26040
</code></pre></div></code></pre>
<p>여러 개가 나오면 한 번에 종료할 수도 있다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash"><span class="hljs-built_in">kill</span> -9 PID1 PID2 PID3
</code></pre></div></code></pre>
<hr>
<h2 id="3-프로젝트-venv의-python-프로세스-전체-종료하기" tabindex="-1" data-src-line="143">3. 프로젝트 venv의 Python 프로세스 전체 종료하기 <a class="header-anchor" href="#3-프로젝트-venv의-python-프로세스-전체-종료하기" aria-hidden="true">#</a></h2>
<p>만약 어떤 프로세스가 정확히 서버인지 애매하다면, 현재 프로젝트의 가상환경 Python 프로세스를 전부 종료할 수 있다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">pkill -9 -f <span class="hljs-string">&quot;/data/data/com.termux/files/home/workspace/my-llm-project/back/venv/bin/python&quot;</span>
</code></pre></div></code></pre>
<p>이 명령은 현재 프로젝트의 <code>venv/bin/python</code>으로 실행 중인 프로세스를 종료한다.</p>
<p>주의할 점은 Code-server의 Python 확장 기능, 예를 들어 Jedi language server 같은 프로세스도 같이 죽을 수 있다는 것이다.</p>
<p>하지만 보통 큰 문제는 아니다. Code-server나 Python 파일을 다시 열면 다시 실행될 수 있다.</p>
<hr>
<h2 id="4-code-server-관련-프로세스까지-확인하기" tabindex="-1" data-src-line="159">4. Code-server 관련 프로세스까지 확인하기 <a class="header-anchor" href="#4-code-server-관련-프로세스까지-확인하기" aria-hidden="true">#</a></h2>
<p>Code-server, Node, Python, Uvicorn, 이전 터미널과 관련된 프로세스를 넓게 확인하려면 다음 명령을 사용한다.</p>

<h2 id="6-8001번은-되는데-8000번만-안-되는-경우" tabindex="-1" data-src-line="191">6. 8001번은 되는데 8000번만 안 되는 경우 <a class="header-anchor" href="#6-8001번은-되는데-8000번만-안-되는-경우" aria-hidden="true">#</a></h2>
<p>8001번 포트로 실행하면 정상 동작하는데 8000번만 실패한다면, 코드 문제보다는 8000번 포트 점유 문제일 가능성이 높다.</p>
<p>예를 들어 다음 명령은 정상 실행된다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">BACKEND_HOST=127.0.0.1 BACKEND_PORT=8001 BACKEND_RELOAD=<span class="hljs-literal">false</span> python main.py
</code></pre></div></code></pre>
<p>하지만 8000번에서는 실패한다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">BACKEND_HOST=127.0.0.1 BACKEND_PORT=8000 BACKEND_RELOAD=<span class="hljs-literal">false</span> python main.py
</code></pre></div></code></pre>
<p>이 경우 8001번으로 우회할 수도 있지만, 기존 프론트엔드나 API 호출 주소가 8000번을 바라보고 있다면 근본적으로 8000번 점유 프로세스를 정리해야 한다.</p>
