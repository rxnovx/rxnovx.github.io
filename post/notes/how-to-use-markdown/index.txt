마크다운을 사용하면서 한가지 느낀점은 문법 이외의 글을 작성할 때 사용하는 방법, 기준에 대해서 정해두어야겠다 싶은 생각이 들어 글을 작성하고자 합니다.</p>

<h2 id="1-헤딩을-나누는-기준" tabindex="-1" data-src-line="14">1️⃣ 헤딩을 나누는 기준 <a class="header-anchor" href="#1-헤딩을-나누는-기준" aria-hidden="true">#</a></h2>
<p>헤딩을 나누는 기준은 여러가지 기준이 있겠지만 저는 보통 목차를 생각하며 헤딩을 나눕니다.<br>
질문이 바뀌는 지점이나, 글의 전체적인 성격이 바뀔 때 헤딩을 새로 정의합니다.</p>
<p>특히 H1 헤딩은 글에서 딱 하나만 존재하도록 합니다. <strong>(H1에 대한 답을 찾아가는 것이 글의 목표)</strong><br>
아래에 좀 더 자세히 설명을 해보겠습니다.</p>
<div class="callout callout-note">
<h3 class="callout-title">핵심원칙</h3><p><strong>질문이 바뀌는 지점 = 헤딩이 바뀌는 지점</strong></p>
</div>
<hr>
<h3 id="h1---이-글이-답하는-단-하나의-질문" tabindex="-1" data-src-line="27">H1 (<code>#</code>) — 이 글이 답하는 단 하나의 질문 <a class="header-anchor" href="#h1---이-글이-답하는-단-하나의-질문" aria-hidden="true">#</a></h3>
<div class="callout callout-note">
<h3 class="callout-title">H1</h3><p>문서 전체에서 <strong>딱 1번만 사용</strong><br>
글의 정체성, 검색 유입의 기준점</p>
</div>
<p>예시:</p>
<pre><code class="language-md"><div class="code-block"><div class="code-header"><span class="code-title">md</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-md"><code class="hljs language-md"><span class="hljs-section"># 안드로이드 태블릿으로 Next.js 개발 환경 구축하기</span>
</code></pre></div></code></pre>
<p>👉 제목만 보고 <strong>이 글이 무엇을 해결해 주는지</strong> 알 수 있어야 함</p>
<hr>
<h3 id="h2---큰-사고-단위--큰-단계" tabindex="-1" data-src-line="43">H2 (<code>##</code>) — 큰 사고 단위 / 큰 단계 <a class="header-anchor" href="#h2---큰-사고-단위--큰-단계" aria-hidden="true">#</a></h3>
<p>가장 큰 틀인 H1의 답을 찾기 위해 또 다시 질문을 할 때 H2 헤딩을 사용합니다.<br>
문단을 나누지 않고 줄줄이 설명하게 된다면 독자가 읽고 이해하기 더 어려워지기 때문에 이렇게 H2 헤딩으로 단계를 나눠 답을 찾도록 합니다.</p>
<div class="callout callout-note">
<h3 class="callout-title">H2</h3><p>“그래서 다음엔 뭘 알아야 하지?”<br>
“이걸 하려면 뭐부터 해야 하지?”</p>
</div>
<p>예시:</p>
<pre><code class="language-md"><div class="code-block"><div class="code-header"><span class="code-title">md</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-md"><code class="hljs language-md"><span class="hljs-section">## 왜 태블릿으로 개발하려 했는가</span>
<span class="hljs-section">## 필요한 준비물</span>
<span class="hljs-section">## 전체 구조 개요</span>
<span class="hljs-section">## 실제 설치 과정</span>
</code></pre></div></code></pre>
<p>👉 <strong>목차에 올라가도 어색하지 않은 단위</strong></p>
<hr>
<h3 id="h3---실제-행동-단위" tabindex="-1" data-src-line="65">H3 (<code>###</code>) — 실제 행동 단위 <a class="header-anchor" href="#h3---실제-행동-단위" aria-hidden="true">#</a></h3>
<p>H2까지 이론에 대한 설명이였다면, H3부터는 실제로 행동해서 결과를 얻을 수 있는 작업에 대해서 서술합니다.</p>
<ul>
<li>손을 움직이는 단계</li>
<li>실행 / 설정 / 클릭 단위</li>
</ul>
<p>예시:</p>
<pre><code class="language-md"><div class="code-block"><div class="code-header"><span class="code-title">md</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-md"><code class="hljs language-md"><span class="hljs-section">### Termux 설치</span>
<span class="hljs-section">### Node.js 설치</span>
<span class="hljs-section">### Next.js 프로젝트 생성</span>
</code></pre></div></code></pre>
<div class="callout callout-note">
<h3 class="callout-title">H3</h3><p>👉 여기서 멈추고 <strong>그대로 따라 해도 되는 단위</strong></p>
</div>
<hr>
<h3 id="h4---옵션--분기--주의사항" tabindex="-1" data-src-line="86">H4 (<code>####</code>) — 옵션 / 분기 / 주의사항 <a class="header-anchor" href="#h4---옵션--분기--주의사항" aria-hidden="true">#</a></h3>
<p>H4는 선택입니다. 내용을 굳이 안해도 되지만, 따라 했을 경우 부가적인 결과가 따라오는 것에 대한 내용을 적습니다.</p>
<ul>
<li>안 해도 되지만 알면 좋은 내용</li>
<li>실수 방지 포인트</li>
</ul>
<p>예시:</p>
<pre><code class="language-md"><div class="code-block"><div class="code-header"><span class="code-title">md</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-md"><code class="hljs language-md"><span class="hljs-section">#### 권장 Node 버전</span>
<span class="hljs-section">#### 에러가 발생하는 경우</span>
</code></pre></div></code></pre>
<div class="callout callout-warning">
<h3 class="callout-title">H4 (주의)</h3><p>👉 H4가 많아지면 글이 산만해짐 (최소화 권장)</p>
</div>
<hr>
<h2 id="2-문법을-쓰는-판단-기준-어떨-때-쓰느냐" tabindex="-1" data-src-line="105">2️⃣ 문법을 쓰는 판단 기준 (“어떨 때 쓰느냐”) <a class="header-anchor" href="#2-문법을-쓰는-판단-기준-어떨-때-쓰느냐" aria-hidden="true">#</a></h2>
<blockquote>
<p>❌ 문법 기능 설명<br>
✅ 이 상황이면 이 문법을 쓴다</p>
</blockquote>
<p>헤딩은 목차를 나누는 단위입니다. #이 많아질수록 중요도가 떨어지는 것이 아니라 점점 더 세부적인 내용으로 들어가는 것입니다.<br>
다음은 다른 문법들입니다. 목록이나 코드블럭, 강조, 구분선 등등의 문법들을 사용하는 방법이 아닌 어떤 상황에 쓰는 것인지 알아봅니다.</p>
<hr>
<h3 id="-목록---1" tabindex="-1" data-src-line="115">📌 목록 (<code>-</code>, <code>1.</code>) <a class="header-anchor" href="#-목록---1" aria-hidden="true">#</a></h3>
<p><strong>언제 쓰나?</strong></p>
<ul>
<li>
<p>나열이 목적일 때</p>
</li>
<li>
<p>문장으로 쓰면 숨 막힐 때</p>
</li>
<li>
<p>순서 중요 ❌ → <code>-</code></p>
</li>
<li>
<p>순서 중요 ⭕ → <code>1. 2. 3.</code></p>
</li>
</ul>
<p>예시:</p>
<pre><code class="language-md"><div class="code-block"><div class="code-header"><span class="code-title">md</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-md"><code class="hljs language-md"><span class="hljs-section">## 준비물</span>

<span class="hljs-bullet">-</span> 인터넷 연결
</code></pre></div></code></pre>
<pre><code class="language-md"><div class="code-block"><div class="code-header"><span class="code-title">md</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-md"><code class="hljs language-md"><span class="hljs-section">## 설치 순서</span>

</code></pre></div></code></pre>

<h3 id="-코드-블록-" tabindex="-1" data-src-line="145">📦 코드 블록 (```) <a class="header-anchor" href="#-코드-블록-" aria-hidden="true">#</a></h3>
<p><strong>언제 쓰나?</strong></p>
<ul>
<li>복사/붙여넣기가 필요한 순간</li>
<li>실행을 요구할 때</li>
</ul>
<p>구조 원칙:</p>
<ul>
<li>설명 → 코드 → 결과</li>
</ul>
<p>예시:</p>
<pre><code class="language-md"><div class="code-block"><div class="code-header"><span class="code-title">md</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-md"><code class="hljs language-md"><span class="hljs-code">``` bash

</code></pre></div></code></pre>
<p>👉 설명 중간에 코드를 끼워 넣지 말 것</p>

<h3 id="-인용-" tabindex="-1" data-src-line="168">🧠 인용 (<code>&gt;</code>) <a class="header-anchor" href="#-인용-" aria-hidden="true">#</a></h3>
<p><strong>언제 쓰나?</strong></p>
<ul>
<li>독자에게 잠깐 멈추게 할 때</li>
<li>주의 / 전제 / 경험 기반 조언</li>
</ul>
<p>예시:</p>
<pre><code class="language-md"><div class="code-block"><div class="code-header"><span class="code-title">md</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-md"><code class="hljs language-md"><span class="hljs-quote">&gt; 이 단계에서 에러가 나면 대부분 권한 문제입니다.</span>

<p>👉 남발하면 훈계처럼 보임</p>

<h3 id="-강조-" tabindex="-1" data-src-line="183">✨ 강조 (<code>**</code>) <a class="header-anchor" href="#-강조-" aria-hidden="true">#</a></h3>

</ul>
<p>예시:</p>

</code></pre></div></code></pre>
<p>👉 한 문장에 1개까지만 사용</p>

<h3 id="-구분선----" tabindex="-1" data-src-line="199">🧱 구분선 (<code>---</code>) <a class="header-anchor" href="#-구분선----" aria-hidden="true">#</a></h3>

<h2 id="5-한-문장-요약" tabindex="-1" data-src-line="236">5️⃣ 한 문장 요약 <a class="header-anchor" href="#5-한-문장-요약" aria-hidden="true">#</a></h2>
<p>마크다운 언어는 생각을 정리하기 정말 좋은 도구라고 생각합니다.<br>
저는 학창시절부터 메모하는 것이 서툴렀는데 마크다운 도구를 활용해서 정리하는 방법에 조금씩 익숙해지고 있습니다.</p>
<blockquote>
<p><strong>마크다운은 꾸미는 도구가 아니라<br>
생각을 계층화하는 도구다.</strong></p>
</blockquote>
<ul>
<li>헤딩 = 생각의 크기</li>
<li>문법 = 독자의 행동을 유도하는 신호</li>
</ul>
