1d:T4a8f,<h1 id="폐쇄망-환경에서-vs-code-remote-ssh-사용하기-오프라인-설치-가이드" tabindex="-1" data-src-line="0">폐쇄망 환경에서 VS Code Remote-SSH 사용하기 (오프라인 설치 가이드) <a class="header-anchor" href="#폐쇄망-환경에서-vs-code-remote-ssh-사용하기-오프라인-설치-가이드" aria-hidden="true">#</a></h1>
<h2 id="들어가기" tabindex="-1" data-src-line="2">들어가기 <a class="header-anchor" href="#들어가기" aria-hidden="true">#</a></h2>
<p>안녕하세요.<br>
오늘은 <strong>폐쇄망 환경에서 VS Code Remote-SSH를 사용하는 방법</strong>에 대해 알아보겠습니다.</p>
<p>보안 정책상 개발 PC에서 외부 인터넷 접근이 제한되거나, 서버에 직접 접속해 터미널 기반으로만 작업해야 하는 환경이 존재합니다.<br>
이러한 경우 서버에서 직접 편집을 진행하면, 로컬 IDE에서 제공되는 자동 완성, 디버깅, 확장 기능 등 기존의 개발 경험을 충분히 활용하기 어렵습니다.</p>
<p>이처럼 <strong>서버 자원을 사용해야 하지만 로컬 개발 환경의 편의성은 유지하고 싶은 상황</strong>에서, 그 대안 중 하나가 VS Code Remote-SSH입니다.</p>
<p>하지만 인터넷에 연결되지 않은 서버에 VS Code 확장 프로그램인 Remote-SSH를 사용해 접근하려고 하면, 기본 설정만으로는 오류가 발생합니다.<br>
이 글에서는 이러한 문제를 해결하기 위해, <strong>폐쇄망 환경에서 Remote-SSH를 정상적으로 사용하기 위한 오프라인 설치 방법</strong>을 단계별로 정리합니다.</p>
<p>또한, 기존에 널리 알려진 스택오버플로우의 방법을 그대로 따라 해도 최근 버전의 VS Code에서는 동일한 오류가 발생할 수 있습니다.<br>
이는 <strong>최근 VS Code 및 Remote-SSH의 내부 동작 방식이 변경되었기 때문</strong>입니다.</p>
<p>본 글은 <strong>이미 VS Code Remote-SSH를 사용해 본 경험이 있는 분</strong>을 대상으로 하며, 기본적인 SSH 개념과 사용법은 다루지 않습니다.</p>

<h3 id="11-대상-독자" tabindex="-1" data-src-line="28">1.1 대상 독자 <a class="header-anchor" href="#11-대상-독자" aria-hidden="true">#</a></h3>
<p>이 글은 다음과 같은 분들을 대상으로 작성되었습니다.</p>
<ul>
<li>VS Code에서 Remote-SSH를 사용해 본 경험이 있는 개발자</li>
<li>폐쇄망(에어갭) 서버에 개발 환경을 구성해야 하는 경우</li>
<li>인터넷이 차단된 서버에서 VS Code 기반 개발을 유지해야 하는 경우</li>
</ul>
<h3 id="12-이-글에서-해결하는-문제" tabindex="-1" data-src-line="36">1.2 이 글에서 해결하는 문제 <a class="header-anchor" href="#12-이-글에서-해결하는-문제" aria-hidden="true">#</a></h3>
<p>이 글에서 다루는 핵심 문제는 다음과 같습니다.</p>
<ul>
<li>Remote-SSH 접속 시 서버에서 vscode-server 다운로드 단계에서 실패하는 문제</li>
<li>기존 <code>~/.vscode-server/bin/&lt;commit&gt;</code> 방식이 동작하지 않는 문제</li>
<li>오프라인 환경에서 vscode-server를 수동으로 설치해야 하는 상황</li>
</ul>
<h3 id="13-폐쇄망-환경의-제약-조건" tabindex="-1" data-src-line="44">1.3 폐쇄망 환경의 제약 조건 <a class="header-anchor" href="#13-폐쇄망-환경의-제약-조건" aria-hidden="true">#</a></h3>
<p>일반적으로 폐쇄망 환경에서는 다음과 같은 제약이 존재합니다.</p>
<ul>
<li>서버에서 외부 인터넷 접근 불가</li>
<li>패키지 매니저를 통한 실시간 다운로드 불가</li>
<li>특정 포트 및 아웃바운드 트래픽 차단</li>
</ul>
<p>이로 인해 VS Code Remote-SSH의 기본 동작 흐름이 정상적으로 완료되지 않습니다.</p>
<hr>
<h2 id="2-remote-ssh가-실패하는-이유" tabindex="-1" data-src-line="56">2. Remote-SSH가 실패하는 이유 <a class="header-anchor" href="#2-remote-ssh가-실패하는-이유" aria-hidden="true">#</a></h2>
<h3 id="21-remote-ssh의-내부-동작-개요" tabindex="-1" data-src-line="58">2.1 Remote-SSH의 내부 동작 개요 <a class="header-anchor" href="#21-remote-ssh의-내부-동작-개요" aria-hidden="true">#</a></h3>
<p>VS Code Remote-SSH는 단순히 SSH로 접속만 하는 확장이 아닙니다.</p>
<p>연결 과정에서 VS Code는 원격 서버에 다음 작업을 수행합니다.</p>
<ul>
<li>vscode-server 바이너리 다운로드</li>
<li>서버 환경에 맞는 실행 파일 압축 해제</li>
<li>원격 서버에서 VS Code와 통신할 백엔드 프로세스 실행</li>
</ul>
<p>이 과정 중 <strong>다운로드 단계가 실패</strong>하면 Remote-SSH 연결 자체가 중단됩니다.</p>
<h3 id="22-폐쇄망에서-발생하는-대표적인-오류" tabindex="-1" data-src-line="70">2.2 폐쇄망에서 발생하는 대표적인 오류 <a class="header-anchor" href="#22-폐쇄망에서-발생하는-대표적인-오류" aria-hidden="true">#</a></h3>
<p>폐쇄망 환경에서는 다음과 같은 오류를 자주 마주치게 됩니다.</p>
<ul>
<li><code>Failed to download VS Code Server</code></li>
<li><code>Waiting for vscode-server to be installed</code></li>
<li>무한 재시도 루프</li>
</ul>
<p>이는 모두 서버에서 외부 네트워크로 접근할 수 없기 때문에 발생하는 문제입니다.</p>
<h3 id="23-기존-스택오버플로우-방식이-실패하는-이유" tabindex="-1" data-src-line="80">2.3 기존 스택오버플로우 방식이 실패하는 이유 <a class="header-anchor" href="#23-기존-스택오버플로우-방식이-실패하는-이유" aria-hidden="true">#</a></h3>
<p>과거에는 <code>~/.vscode-server/bin/&lt;commit&gt;</code> 경로에 미리 다운로드한 파일을 복사하는 방식으로 문제를 해결할 수 있었습니다.</p>
<p>하지만 최근 버전의 VS Code Remote-SSH에서는 <strong>서버 설치 경로 및 실행 방식이 변경</strong>되었고, 이로 인해 기존 방식이 더 이상 통하지 않는 경우가 많아졌습니다.</p>
<hr>
<h2 id="3-최근-vs-code--remote-ssh의-변경점" tabindex="-1" data-src-line="88">3. 최근 VS Code / Remote-SSH의 변경점 <a class="header-anchor" href="#3-최근-vs-code--remote-ssh의-변경점" aria-hidden="true">#</a></h2>
<h3 id="31-기존-방식-vscode-serverbincommit" tabindex="-1" data-src-line="90">3.1 기존 방식: <code>~/.vscode-server/bin/&lt;commit&gt;</code> <a class="header-anchor" href="#31-기존-방식-vscode-serverbincommit" aria-hidden="true">#</a></h3>
<p>과거 Remote-SSH는 커밋 ID 기준으로 다음 경로에 서버 파일을 설치했습니다.</p>
<pre><code><div class="code-block"><div class="code-header"><span class="code-title">unknown</span><button class="copy-button">Copy</button></div><pre class="language-plain"><code>~<span class="hljs-regexp">/.vscode-server/</span>bin<span class="hljs-regexp">/&lt;commit&gt;/</span>
</code></pre></div></code></pre>
<p>이 경로에 파일이 존재하면 다운로드 과정을 건너뛰었습니다.</p>
<h3 id="32-최신-방식-cliserversstable-commit" tabindex="-1" data-src-line="100">3.2 최신 방식: <code>cli/servers/Stable-&lt;commit&gt;</code> <a class="header-anchor" href="#32-최신-방식-cliserversstable-commit" aria-hidden="true">#</a></h3>
<p>최근 버전에서는 다음과 같은 새로운 경로가 사용됩니다.</p>
<pre><code><div class="code-block"><div class="code-header"><span class="code-title">unknown</span><button class="copy-button">Copy</button></div><pre class="language-plain"><code>~/.vscode-<span class="hljs-keyword">server</span>/code-&lt;<span class="hljs-keyword">commit</span>&gt;

</code></pre></div></code></pre>
<p>이 변화로 인해 기존 경로에 파일을 복사해도 Remote-SSH가 이를 인식하지 못하는 상황이 발생합니다.</p>
<h3 id="33-내-환경에서-사용-중인-방식-확인하기" tabindex="-1" data-src-line="111">3.3 내 환경에서 사용 중인 방식 확인하기 <a class="header-anchor" href="#33-내-환경에서-사용-중인-방식-확인하기" aria-hidden="true">#</a></h3>
<p>현재 사용 중인 방식은 VS Code의 <strong>Remote-SSH Output 로그</strong>를 통해 확인할 수 있습니다.</p>
<p>로그에 다음과 같은 문자열이 포함되어 있다면 최신 방식입니다.</p>
<ul>
<li><code>cli/servers/Stable-&lt;commit&gt;/server/bin/code-server</code></li>
</ul>

<h2 id="4-사전-준비-체크리스트" tabindex="-1" data-src-line="121">4. 사전 준비 체크리스트 <a class="header-anchor" href="#4-사전-준비-체크리스트" aria-hidden="true">#</a></h2>
<h3 id="41-서버-os-및-아키텍처-확인" tabindex="-1" data-src-line="123">4.1 서버 OS 및 아키텍처 확인 <a class="header-anchor" href="#41-서버-os-및-아키텍처-확인" aria-hidden="true">#</a></h3>
<p>서버의 운영체제와 CPU 아키텍처(x64, arm64 등)를 정확히 확인해야 합니다.</p>
<p>잘못된 아키텍처의 바이너리를 사용할 경우 실행 단계에서 실패합니다.</p>
<h3 id="42-vs-code-버전-및-commit-id-확인" tabindex="-1" data-src-line="129">4.2 VS Code 버전 및 Commit ID 확인 <a class="header-anchor" href="#42-vs-code-버전-및-commit-id-확인" aria-hidden="true">#</a></h3>
<p>VS Code는 커밋 ID 기준으로 버전을 관리합니다.</p>
<p>로컬 PC에서 사용 중인 VS Code의 <strong>Commit ID</strong>를 반드시 확인해 두어야 합니다.</p>

<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-keyword">code</span> -v

x64 # 아키텍처

<h3 id="51-인터넷-가능한-pc에서-파일-준비" tabindex="-1" data-src-line="155">5.1 인터넷 가능한 PC에서 파일 준비 <a class="header-anchor" href="#51-인터넷-가능한-pc에서-파일-준비" aria-hidden="true">#</a></h3>

<h3 id="61-최신-경로-기준-설치-방법" tabindex="-1" data-src-line="177">6.1 최신 경로 기준 설치 방법 <a class="header-anchor" href="#61-최신-경로-기준-설치-방법" aria-hidden="true">#</a></h3>
<p>다운로드 한 두 파일을 특정 폴더에 지정해서 넣어두고 아래의 스크립트를 실행합니다.</p>

<h3 id="62-스크립트-설명" tabindex="-1" data-src-line="212">6.2 스크립트 설명 <a class="header-anchor" href="#62-스크립트-설명" aria-hidden="true">#</a></h3>
<ul>
<li>1단계: vscode-cli 압축을 해제하여 code 실행 파일을 준비합니다.</li>
<li>2단계: code 바이너리를 Commit ID 기준 이름으로 복사합니다.</li>
<li>3단계: 최신 Remote-SSH가 인식하는 서버 설치 경로를 생성합니다.</li>
<li>4단계: 서버용 VS Code 바이너리를 해당 경로에 압축 해제합니다.</li>
<li>5단계: 퍼미션 문제로 인한 재설치 루프를 방지하기 위해 권한을 정리합니다.</li>
</ul>
<p>이 단계까지 완료되면, Remote-SSH가 서버에 추가 다운로드를 시도하지 않고 기존 파일을 사용하게 됩니다.</p>

<h3 id="81-commit-id-불일치" tabindex="-1" data-src-line="239">8.1 Commit ID 불일치 <a class="header-anchor" href="#81-commit-id-불일치" aria-hidden="true">#</a></h3>
<p>VS Code가 업데이트되면 Commit ID가 변경되며, 기존 서버 파일이 재사용되지 않습니다.</p>
<p>VS Code 업데이트를 진행하게 되면 위의 과정을 반복해주시면 됩니다.</p>

<p>서버 아키텍처와 다른 바이너리를 사용하는 경우 실행이 불가능합니다.</p>
<h3 id="83-퍼미션-및-홈-디렉토리-문제" tabindex="-1" data-src-line="249">8.3 퍼미션 및 홈 디렉토리 문제 <a class="header-anchor" href="#83-퍼미션-및-홈-디렉토리-문제" aria-hidden="true">#</a></h3>
<p>NFS 홈 디렉토리 또는 제한된 권한 환경에서는 추가 설정이 필요할 수 있습니다.</p>
