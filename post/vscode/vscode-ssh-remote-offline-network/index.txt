<h2 id="들어가기" tabindex="-1" data-src-line="2">들어가기 <a class="header-anchor" href="#들어가기" aria-hidden="true">#</a></h2>
<p>안녕하세요.<br>
오늘은 <strong>폐쇄망 환경에서 VS Code Remote-SSH를 사용하는 방법</strong>에 대해 알아보겠습니다.</p>
<p>보안 정책상 개발 PC에서 외부 인터넷 접근이 제한되거나, 서버에 직접 접속해 터미널 기반으로만 작업해야 하는 환경이 존재합니다.<br>
이러한 경우 서버에서 직접 편집을 진행하면, 로컬 IDE에서 제공되는 자동 완성, 디버깅, 확장 기능 등 기존의 개발 경험을 충분히 활용하기 어렵습니다.</p>
<p>이처럼 <strong>서버 자원을 사용해야 하지만 로컬 개발 환경의 편의성은 유지하고 싶은 상황</strong>에서, 그 대안 중 하나가 VS Code Remote-SSH입니다.</p>
<p>하지만 인터넷에 연결되지 않은 서버에 VS Code 확장 프로그램인 Remote-SSH를 사용해 접근하려고 하면, 기본 설정만으로는 오류가 발생합니다.<br>
이 글에서는 이러한 문제를 해결하기 위해, <strong>폐쇄망 환경에서 Remote-SSH를 정상적으로 사용하기 위한 오프라인 설치 방법</strong>을 단계별로 정리합니다.</p>
<p>또한, 기존에 널리 알려진 스택오버플로우의 방법을 그대로 따라 해도 최근 버전의 VS Code에서는 동일한 오류가 발생할 수 있습니다.<br>
이는 <strong>최근 VS Code 및 Remote-SSH의 내부 동작 방식이 변경되었기 때문</strong>입니다.</p>
<p>본 글은 <strong>이미 VS Code Remote-SSH를 사용해 본 경험이 있는 분</strong>을 대상으로 하며, 기본적인 SSH 개념과 사용법은 다루지 않습니다.</p>

<h2 id="2-remote-ssh가-실패하는-이유" tabindex="-1" data-src-line="58">2. Remote-SSH가 실패하는 이유 <a class="header-anchor" href="#2-remote-ssh가-실패하는-이유" aria-hidden="true">#</a></h2>
<h3 id="21-remote-ssh의-내부-동작-개요" tabindex="-1" data-src-line="60">2.1 Remote-SSH의 내부 동작 개요 <a class="header-anchor" href="#21-remote-ssh의-내부-동작-개요" aria-hidden="true">#</a></h3>
<p>VS Code Remote-SSH는 단순히 SSH로 접속만 하는 확장이 아닙니다.</p>
<p>연결 과정에서 VS Code는 원격 서버에 다음 작업을 수행합니다.</p>
<ul>
<li>vscode-server 바이너리 다운로드</li>
<li>서버 환경에 맞는 실행 파일 압축 해제</li>
<li>원격 서버에서 VS Code와 통신할 백엔드 프로세스 실행</li>
</ul>
<p>이 과정 중 <strong>다운로드 단계가 실패</strong>하면 Remote-SSH 연결 자체가 중단됩니다.</p>
<h3 id="22-폐쇄망에서-발생하는-대표적인-오류" tabindex="-1" data-src-line="72">2.2 폐쇄망에서 발생하는 대표적인 오류 <a class="header-anchor" href="#22-폐쇄망에서-발생하는-대표적인-오류" aria-hidden="true">#</a></h3>
<p>폐쇄망 환경에서는 다음과 같은 오류를 자주 마주치게 됩니다.</p>
<ul>
<li><code>Failed to download VS Code Server</code></li>
<li><code>Waiting for vscode-server to be installed</code></li>
<li>무한 재시도 루프</li>
</ul>
<p>이는 모두 서버에서 외부 네트워크로 접근할 수 없기 때문에 발생하는 문제입니다.</p>
<h3 id="23-기존-스택오버플로우-방식이-실패하는-이유" tabindex="-1" data-src-line="82">2.3 기존 스택오버플로우 방식이 실패하는 이유 <a class="header-anchor" href="#23-기존-스택오버플로우-방식이-실패하는-이유" aria-hidden="true">#</a></h3>
<p>과거에는 <code>~/.vscode-server/bin/&lt;commit&gt;</code> 경로에 미리 다운로드한 파일을 복사하는 방식으로 문제를 해결할 수 있었습니다.</p>
<p>하지만 최근 버전의 VS Code Remote-SSH에서는 <strong>서버 설치 경로 및 실행 방식이 변경</strong>되었고, 이로 인해 기존 방식이 더 이상 통하지 않는 경우가 많아졌습니다.</p>

<h3 id="62-스크립트-설명" tabindex="-1" data-src-line="214">6.2 스크립트 설명 <a class="header-anchor" href="#62-스크립트-설명" aria-hidden="true">#</a></h3>
<ul>
<li>1단계: vscode-cli 압축을 해제하여 code 실행 파일을 준비합니다.</li>
<li>2단계: code 바이너리를 Commit ID 기준 이름으로 복사합니다.</li>
<li>3단계: 최신 Remote-SSH가 인식하는 서버 설치 경로를 생성합니다.</li>
<li>4단계: 서버용 VS Code 바이너리를 해당 경로에 압축 해제합니다.</li>
<li>5단계: 퍼미션 문제로 인한 재설치 루프를 방지하기 위해 권한을 정리합니다.</li>
</ul>
<p>이 단계까지 완료되면, Remote-SSH가 서버에 추가 다운로드를 시도하지 않고 기존 파일을 사용하게 됩니다.</p>

<h2 id="7-remote-ssh-연결-확인" tabindex="-1" data-src-line="227">7. Remote-SSH 연결 확인 <a class="header-anchor" href="#7-remote-ssh-연결-확인" aria-hidden="true">#</a></h2>
<h3 id="71-vs-code에서-재접속" tabindex="-1" data-src-line="229">7.1 VS Code에서 재접속 <a class="header-anchor" href="#71-vs-code에서-재접속" aria-hidden="true">#</a></h3>
<p>설치가 완료되면 VS Code에서 Remote-SSH로 다시 접속을 시도합니다.</p>
<h3 id="72-정상-동작-여부-확인" tabindex="-1" data-src-line="233">7.2 정상 동작 여부 확인 <a class="header-anchor" href="#72-정상-동작-여부-확인" aria-hidden="true">#</a></h3>
<p>정상적으로 연결되었다면 연결 완료 후 아무 에러 없이 VS Code 창이 뜨는 걸 확인할 수 있습니다.</p>
<hr>
<h2 id="8-자주-발생하는-문제와-해결-방법" tabindex="-1" data-src-line="239">8. 자주 발생하는 문제와 해결 방법 <a class="header-anchor" href="#8-자주-발생하는-문제와-해결-방법" aria-hidden="true">#</a></h2>
<h3 id="81-commit-id-불일치" tabindex="-1" data-src-line="241">8.1 Commit ID 불일치 <a class="header-anchor" href="#81-commit-id-불일치" aria-hidden="true">#</a></h3>
<p>VS Code가 업데이트되면 Commit ID가 변경되며, 기존 서버 파일이 재사용되지 않습니다.</p>
<p>VS Code 업데이트를 진행하게 되면 위의 과정을 반복해주시면 됩니다.</p>
<h3 id="82-아키텍처-불일치" tabindex="-1" data-src-line="247">8.2 아키텍처 불일치 <a class="header-anchor" href="#82-아키텍처-불일치" aria-hidden="true">#</a></h3>
<p>서버 아키텍처와 다른 바이너리를 사용하는 경우 실행이 불가능합니다.</p>
<h3 id="83-퍼미션-및-홈-디렉토리-문제" tabindex="-1" data-src-line="251">8.3 퍼미션 및 홈 디렉토리 문제 <a class="header-anchor" href="#83-퍼미션-및-홈-디렉토리-문제" aria-hidden="true">#</a></h3>
<p>NFS 홈 디렉토리 또는 제한된 권한 환경에서는 추가 설정이 필요할 수 있습니다.</p>

<h2 id="9-운영-팁" tabindex="-1" data-src-line="257">9. 운영 팁 <a class="header-anchor" href="#9-운영-팁" aria-hidden="true">#</a></h2>

<p>폐쇄망 환경에서는 VS Code 버전을 고정해 사용하는 것이 관리 측면에서 유리합니다.</p>
<h3 id="92-팀-단위-배포-전략" tabindex="-1" data-src-line="263">9.2 팀 단위 배포 전략 <a class="header-anchor" href="#92-팀-단위-배포-전략" aria-hidden="true">#</a></h3>
