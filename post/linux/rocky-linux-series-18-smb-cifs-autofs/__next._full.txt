<h2 id="smb--cifs란-무엇인가" tabindex="-1" data-src-line="17">SMB / CIFS란 무엇인가 <a class="header-anchor" href="#smb--cifs란-무엇인가" aria-hidden="true">#</a></h2>
<p>SMB(Server Message Block)는 주로 <strong>Windows 환경</strong>에서 사용되던 파일 공유 프로토콜입니다.<br>
리눅스에서는 오랫동안 <strong>Samba</strong>라는 구현체를 통해 SMB를 사용해왔고, 과거에는 CIFS라는 이름으로 더 자주 불렸습니다.</p>
<p>현재 기준으로는 다음처럼 이해하시면 됩니다.</p>
<ul>
<li><strong>SMB</strong> : 프로토콜의 공식 명칭</li>
<li><strong>CIFS</strong> : SMB 1.x 계열을 지칭하던 옛 이름</li>
<li><strong>Samba</strong> : 리눅스/유닉스에서 SMB를 구현한 소프트웨어</li>
</ul>
<p>리눅스에서 Windows 공유 폴더를 마운트한다는 말은,<br>
결국 <strong>SMB(CIFS)를 통해 네트워크 파일시스템을 붙인다</strong>는 의미입니다.</p>

<h2 id="smb-서버-확인-smbclient" tabindex="-1" data-src-line="59">SMB 서버 확인 (smbclient) <a class="header-anchor" href="#smb-서버-확인-smbclient" aria-hidden="true">#</a></h2>
<p>마운트 전에, 해당 서버가 어떤 공유를 제공하는지 확인하는 것이 좋습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-attribute">smbclient</span> -L <span class="hljs-number">59.29.224.185</span>
</code></pre></div></code></pre>
<p>이 명령은 다음을 확인하는 용도입니다.</p>
<ul>
<li>서버가 살아 있는지</li>
<li>어떤 공유 이름이 존재하는지</li>
<li>인증이 필요한지</li>
</ul>
<p>실무에서는 <strong>이 단계에서 대부분의 오타와 설정 오류를 잡습니다.</strong></p>
<hr>
<h2 id="cifs-수동-마운트" tabindex="-1" data-src-line="77">CIFS 수동 마운트 <a class="header-anchor" href="#cifs-수동-마운트" aria-hidden="true">#</a></h2>
<p>마운트 포인트를 하나 준비합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-built_in">mkdir</span> /mnt/win
</code></pre></div></code></pre>
<p>이제 CIFS 타입으로 직접 마운트합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-attribute">mount</span> -t cifs -o user=hpe,vers=<span class="hljs-number">1</span>.<span class="hljs-number">0</span> //<span class="hljs-number">59.29.224.185</span>/windata /mnt/win
</code></pre></div></code></pre>
<p>여기서 중요한 포인트는 다음입니다.</p>
<ul>
<li><code>//서버IP/공유이름</code> 형식</li>
<li><code>vers=</code> 옵션은 <strong>SMB 프로토콜 버전</strong></li>
<li>오래된 장비나 NAS는 1.0을 요구하는 경우가 있음</li>
</ul>
<p>마운트가 되었다면 <code>/mnt/win</code> 아래에서 바로 파일 접근이 가능합니다.</p>
<hr>
<h2 id="자격-증명-파일-사용하기" tabindex="-1" data-src-line="101">자격 증명 파일 사용하기 <a class="header-anchor" href="#자격-증명-파일-사용하기" aria-hidden="true">#</a></h2>
<p>명령줄에 사용자 이름과 비밀번호를 직접 쓰는 방식은 운영 환경에서 적절하지 않습니다.<br>
이를 위해 <strong>credential 파일</strong>을 사용합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code>vi <span class="hljs-regexp">/root/</span>credential.cre
</code></pre></div></code></pre>
<pre><code class="language-text"><div class="code-block"><div class="code-header"><span class="code-title">text</span><button class="copy-button">Copy</button></div><pre class="language-text"><code><span class="hljs-attribute">username</span><span class="hljs-operator">=</span>hpe
<span class="hljs-attribute">password</span><span class="hljs-operator">=</span>비밀번호
</code></pre></div></code></pre>
<p>권한은 반드시 제한합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-built_in">chmod</span> 600 /root/credential.cre
</code></pre></div></code></pre>
<p>이제 <code>/etc/fstab</code>에 등록합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-regexp">//</span><span class="hljs-number">59.29</span>.<span class="hljs-number">224.185</span><span class="hljs-regexp">/windata  /m</span>nt<span class="hljs-regexp">/win  cifs  defaults,vers=1.0,credentials=/</span>root/credential.cre  <span class="hljs-number">0</span> <span class="hljs-number">0</span>
</code></pre></div></code></pre>
<p>이 방식의 장점은 다음과 같습니다.</p>
<ul>
<li>재부팅 시 자동 마운트 가능</li>
<li>비밀번호 노출 최소화</li>
<li>설정 관리 용이</li>
</ul>
<hr>
<h2 id="autofs가-필요한-이유" tabindex="-1" data-src-line="135">AutoFS가 필요한 이유 <a class="header-anchor" href="#autofs가-필요한-이유" aria-hidden="true">#</a></h2>
<p><code>/etc/fstab</code> 기반의 마운트에는 한계가 있습니다.</p>
<ul>
<li>서버가 일시적으로 내려가면 부팅이 멈출 수 있음</li>
<li>사용하지 않아도 항상 마운트 유지</li>
<li>네트워크 장애에 취약</li>
</ul>
<p>이를 해결하기 위해 등장한 것이 <strong>AutoFS</strong>입니다.</p>
<p>AutoFS는 다음처럼 동작합니다.</p>
<ul>
<li>디렉토리에 접근하는 순간 자동 마운트</li>
<li>일정 시간 사용하지 않으면 자동 언마운트</li>
<li>네트워크 스토리지에 매우 적합</li>
</ul>
<hr>
<h2 id="autofs-기본-구조" tabindex="-1" data-src-line="153">AutoFS 기본 구조 <a class="header-anchor" href="#autofs-기본-구조" aria-hidden="true">#</a></h2>
<p>AutoFS는 두 단계 설정 구조를 가집니다.</p>
<ol>
<li><strong>마스터 설정</strong> : 어떤 경로를 AutoFS가 관리할지</li>
<li><strong>맵 파일</strong> : 실제 마운트 규칙</li>
</ol>
<p>RHEL 8 이후에는 <code>/etc/auto.master</code>를 직접 수정하지 않고,<br>
<code>/etc/auto.master.d/</code> 아래에 파일을 추가하는 방식을 권장합니다.</p>
<p>확장자는 반드시 <code>.autofs</code> 로 끝나야 합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code>dnf install autofs
<span class="hljs-built_in">ls</span> /etc/auto.master
<span class="hljs-built_in">ls</span> /etc/auto.master.d
</code></pre></div></code></pre>
<hr>
<h2 id="다이렉트-맵-방식-direct-map" tabindex="-1" data-src-line="173">다이렉트 맵 방식 (Direct Map) <a class="header-anchor" href="#다이렉트-맵-방식-direct-map" aria-hidden="true">#</a></h2>
<p>다이렉트 맵은 <strong>절대 경로 하나를 특정 공유에 바로 연결</strong>하는 방식입니다.</p>
<h3 id="마스터-설정" tabindex="-1" data-src-line="177">마스터 설정 <a class="header-anchor" href="#마스터-설정" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code>vi /etc/<span class="hljs-built_in">auto</span>.master.d/good.<span class="hljs-built_in">auto</span>fs
</code></pre></div></code></pre>
<pre><code class="language-text"><div class="code-block"><div class="code-header"><span class="code-title">text</span><button class="copy-button">Copy</button></div><pre class="language-text"><code>/-    /etc/morning
</code></pre></div></code></pre>
<p><code>/-</code> 는 다이렉트 맵을 의미합니다.</p>
<h3 id="맵-파일" tabindex="-1" data-src-line="189">맵 파일 <a class="header-anchor" href="#맵-파일" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code>vi <span class="hljs-regexp">/etc/m</span>orning
</code></pre></div></code></pre>
<pre><code class="language-text"><div class="code-block"><div class="code-header"><span class="code-title">text</span><button class="copy-button">Copy</button></div><pre class="language-text"><code><span class="hljs-regexp">/win  -fstype=cifs,vers=1.0,credentials=/</span>root<span class="hljs-regexp">/credential.cre  :/</span><span class="hljs-regexp">/59.29.224.185/</span>windata
</code></pre></div></code></pre>
<p>CIFS의 경우 <strong>경로 앞에 콜론(:)</strong> 을 반드시 붙입니다.</p>
<p>서비스를 시작합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code>systemctl start <span class="hljs-built_in">auto</span>fs
</code></pre></div></code></pre>
<p>이제 <code>/win</code> 디렉토리에 접근하는 순간 자동으로 마운트됩니다.</p>
<hr>
<h2 id="인다이렉트-맵-방식-indirect-map" tabindex="-1" data-src-line="211">인다이렉트 맵 방식 (Indirect Map) <a class="header-anchor" href="#인다이렉트-맵-방식-indirect-map" aria-hidden="true">#</a></h2>
<p>인다이렉트 맵은 <strong>상위 디렉토리 아래에 여러 하위 마운트</strong>를 만드는 방식입니다.<br>
사용자 홈 디렉토리 구성에 매우 자주 사용됩니다.</p>
<h3 id="서버-측-nfs-예시" tabindex="-1" data-src-line="216">서버 측 (NFS 예시) <a class="header-anchor" href="#서버-측-nfs-예시" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code>vi /etc/exports
/netusers *(rw,<span class="hljs-built_in">sync</span>)
</code></pre></div></code></pre>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-built_in">mkdir</span> -p /netusers/{tom,susan,harry}
exportfs -var
</code></pre></div></code></pre>
<h3 id="클라이언트-측" tabindex="-1" data-src-line="228">클라이언트 측 <a class="header-anchor" href="#클라이언트-측" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code>vi /etc/<span class="hljs-built_in">auto</span>.master.d/my.<span class="hljs-built_in">auto</span>fs
</code></pre></div></code></pre>
<pre><code class="language-text"><div class="code-block"><div class="code-header"><span class="code-title">text</span><button class="copy-button">Copy</button></div><pre class="language-text"><code>/users   /etc/day
</code></pre></div></code></pre>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code>vi /etc/<span class="hljs-built_in">day</span>
</code></pre></div></code></pre>
<pre><code class="language-text"><div class="code-block"><div class="code-header"><span class="code-title">text</span><button class="copy-button">Copy</button></div><pre class="language-text"><code>*   <span class="hljs-number">192.168</span>.<span class="hljs-number">11.33</span><span class="hljs-symbol">:/netusers/&amp;</span>
</code></pre></div></code></pre>
<p><code>*</code> 와 <code>&amp;</code> 를 사용하면,<br>
사용자 수가 늘어나도 설정을 한 줄로 유지할 수 있습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code>systemctl restart <span class="hljs-built_in">auto</span>fs
</code></pre></div></code></pre>
<p>이제 <code>/users/tom</code>, <code>/users/susan</code> 처럼 접근 시 자동으로 마운트됩니다.</p>
<hr>
<h2 id="네트워크-계정과-홈-디렉토리-문제" tabindex="-1" data-src-line="257">네트워크 계정과 홈 디렉토리 문제 <a class="header-anchor" href="#네트워크-계정과-홈-디렉토리-문제" aria-hidden="true">#</a></h2>
<p>LDAP, IPA, AD 같은 <strong>중앙 계정 관리 시스템</strong>을 사용하면,<br>
계정 정보는 공유되지만 <strong>로컬 홈 디렉토리는 자동으로 생성되지 않습니다.</strong></p>
<p>홈 디렉토리가 없으면:</p>
<ul>
<li>작업 공간이 없음</li>
<li>쉘 환경 구성 불가</li>
<li>실질적인 사용이 어려움</li>
</ul>
<p>이 문제를 해결하는 가장 일반적인 방식이 바로:</p>
<ul>
<li>NFS로 홈 디렉토리 중앙화</li>
<li>AutoFS로 사용자 접근 시 자동 마운트</li>
</ul>
<p>입니다.</p>
<hr>
<h2 id="정리하며" tabindex="-1" data-src-line="277">정리하며 <a class="header-anchor" href="#정리하며" aria-hidden="true">#</a></h2>
<p>이번 글에서는 다음 흐름을 정리했습니다.</p>
<ul>
<li>SMB(CIFS)를 이용한 네트워크 스토리지 사용</li>
<li>수동 마운트와 credential 관리</li>
<li>AutoFS의 구조와 필요성</li>
<li>다이렉트 맵과 인다이렉트 맵</li>
<li>중앙 계정 환경에서의 홈 디렉토리 설계</li>
</ul>
<p>네트워크 스토리지는 설정 자체보다,<br>
<strong>운영 시 어떤 문제가 생기는지까지 고려하는 것</strong>이 더 중요합니다.<br>
AutoFS는 그 고민을 상당 부분 덜어주는 도구입니다.</p>
