<h2 id="들어가기" tabindex="-1" data-src-line="4">들어가기 <a class="header-anchor" href="#들어가기" aria-hidden="true">#</a></h2>
<p>프로세스 관리는 리눅스를 다룰 때 가장 자주 마주치는 영역 중 하나입니다.<br>
명령어를 실행하고, 멈추고, 백그라운드로 보내는 모든 동작은 결국 프로세스 관리로 귀결됩니다.</p>
<p>이 글에서는 프로세스의 정의를 나열하는 데서 그치지 않고,<br>
<strong>운영 중 실제로 언제 어떤 판단을 해야 하는지</strong>를 기준으로 정리합니다.</p>
<hr>
<h2 id="프로세스란-무엇인가요" tabindex="-1" data-src-line="14">프로세스란 무엇인가요? <a class="header-anchor" href="#프로세스란-무엇인가요" aria-hidden="true">#</a></h2>
<p>프로세스는 <strong>메모리에 적재되어 실행 중인 프로그램</strong>을 의미합니다.<br>
디스크에 존재하는 실행 파일은 아직 프로세스가 아니며,<br>
실행되는 순간 운영체제로부터 PID를 부여받고 프로세스로 관리됩니다.</p>
<p>리눅스 시스템은 하나의 CPU 위에서 여러 프로세스를 처리합니다.<br>
이를 위해 <strong>시분할(Time Sharing)</strong> 방식을 사용하며,<br>
짧은 시간 단위로 CPU를 나누어 사용하기 때문에 동시에 실행되는 것처럼 보이게 됩니다.</p>
<hr>
<h2 id="프로세스는-어떤-정보로-관리될까요" tabindex="-1" data-src-line="26">프로세스는 어떤 정보로 관리될까요? <a class="header-anchor" href="#프로세스는-어떤-정보로-관리될까요" aria-hidden="true">#</a></h2>
<p>리눅스는 각 프로세스를 단순한 실행 단위가 아닌,<br>
여러 속성을 가진 객체처럼 관리합니다.</p>
<ul>
<li><strong>PID (Process ID)</strong> : 프로세스를 구분하기 위한 고유 번호입니다.</li>
<li><strong>Priority</strong> : CPU 스케줄링 시 적용되는 우선순위입니다.</li>
<li><strong>Nice value</strong> : Priority에 영향을 주는 보정 값으로, 낮을수록 우선순위가 높습니다.</li>
<li><strong>Memory</strong> : 코드, 데이터, 힙, 스택 영역을 포함한 메모리 사용 정보입니다.</li>
<li><strong>Security context</strong> : SELinux에서 사용하는 보안 정책 정보입니다.</li>
<li><strong>Environment</strong> : 실행 시 전달된 환경 변수 집합입니다.</li>
<li><strong>File handles</strong> : 열려 있는 파일, 소켓, 파이프 디스크립터입니다.</li>
<li><strong>Exit status</strong> : 종료 시 부모 프로세스에게 전달되는 결과 코드입니다.</li>
</ul>
<p>이 정보들은 단순 조회용이 아니라,<br>
문제 상황에서 원인을 추적하는 단서로 사용됩니다.</p>
<hr>
<h2 id="pid-1은-왜-중요할까요-init--systemd" tabindex="-1" data-src-line="45">PID 1은 왜 중요할까요? (init → systemd) <a class="header-anchor" href="#pid-1은-왜-중요할까요-init--systemd" aria-hidden="true">#</a></h2>
<p>리눅스에서 <strong>PID 1</strong>은 시스템의 시작점입니다.<br>
부팅이 완료되면 가장 먼저 실행되며,<br>
다른 모든 프로세스의 조상이 됩니다.</p>
<p>초기 리눅스에서는 <code>init</code>이 이 역할을 담당했습니다.<br>
SysV init 방식은 스크립트를 순차적으로 실행하는 구조였으며,<br>
단순하지만 부팅 속도가 느리고 의존성 관리가 어렵다는 문제가 있었습니다.</p>
<p>이를 개선하기 위해 등장한 것이 <strong>systemd</strong>입니다.<br>
systemd 역시 PID 1로 동작하지만,<br>
unit 기반으로 서비스를 관리하고 병렬 실행을 지원합니다.</p>
<p>이로 인해 부팅 속도가 개선되었고,<br>
서비스 상태 확인과 재시작, 로그 관리가 표준화되었습니다.</p>
<ul>
<li>init : 스크립트 기반, 순차 실행</li>
<li>systemd : unit 기반, 병렬 실행</li>
</ul>
<hr>
<h2 id="프로세스-상태는-언제-확인해야-할까요" tabindex="-1" data-src-line="67">프로세스 상태는 언제 확인해야 할까요? <a class="header-anchor" href="#프로세스-상태는-언제-확인해야-할까요" aria-hidden="true">#</a></h2>
<p>프로세스는 실행 중 상황에 따라 여러 상태를 오갑니다.<br>
상태를 이해하면, 프로세스가 멈춘 이유를 추측할 수 있습니다.</p>
<ul>
<li><strong>running</strong> : CPU를 할당받아 실행 중이거나 실행 가능한 상태입니다.</li>
<li><strong>sleeping</strong> : 이벤트나 자원을 기다리는 정상 대기 상태입니다.</li>
<li><strong>uninterruptible sleep</strong> : I/O 작업을 기다리며 시그널로도 깨어나지 않는 상태입니다.</li>
<li><strong>stopped</strong> : SIGSTOP, SIGTSTP 등에 의해 일시 정지된 상태입니다.</li>
<li><strong>zombie</strong> : 실행은 종료되었으나 종료 상태가 회수되지 않은 상태입니다.</li>
</ul>
<p>특히 zombie 상태는 프로세스 자체보다<br>
부모 프로세스의 처리 문제를 의심해야 하는 신호입니다.</p>
<hr>
<h2 id="프로세스를-어떻게-확인할까요" tabindex="-1" data-src-line="83">프로세스를 어떻게 확인할까요? <a class="header-anchor" href="#프로세스를-어떻게-확인할까요" aria-hidden="true">#</a></h2>
<h3 id="ps--현재-실행-중인-프로세스-확인" tabindex="-1" data-src-line="85">ps : 현재 실행 중인 프로세스 확인 <a class="header-anchor" href="#ps--현재-실행-중인-프로세스-확인" aria-hidden="true">#</a></h3>
<p><code>ps</code>는 특정 시점의 프로세스 상태를 확인할 때 사용합니다.<br>
로그인한 터미널에서 어떤 프로세스가 실행 중인지 확인할 때 유용합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">ps
ps -f
ps --forest
</code></pre></div></code></pre>
<p><code>PPID</code>를 함께 확인하면,<br>
해당 프로세스가 어떤 부모 프로세스에 의해 실행되었는지 파악할 수 있습니다.</p>
<hr>
<h3 id="top--실시간-상태-확인" tabindex="-1" data-src-line="101">top : 실시간 상태 확인 <a class="header-anchor" href="#top--실시간-상태-확인" aria-hidden="true">#</a></h3>
<p><code>top</code>은 시스템이 느려졌다고 느껴질 때 가장 먼저 실행하는 명령어입니다.</p>
<ul>
<li><strong>Shift + P</strong> : CPU 사용량 기준 정렬</li>
<li><strong>Shift + M</strong> : 메모리 사용량 기준 정렬</li>
</ul>
<p>특정 프로세스가 자원을 과도하게 사용하고 있는지<br>
빠르게 파악할 수 있습니다.</p>
<hr>
<h2 id="시그널은-언제-사용해야-할까요" tabindex="-1" data-src-line="113">시그널은 언제 사용해야 할까요? <a class="header-anchor" href="#시그널은-언제-사용해야-할까요" aria-hidden="true">#</a></h2>
<p>시그널은 프로세스에게 동작을 요청하는 수단입니다.<br>
운영체제 내부뿐 아니라, 사용자가 직접 전달할 수도 있습니다.</p>
<ul>
<li>커널 → 프로세스</li>
<li>프로세스 → 프로세스</li>
<li>사용자 → 프로세스</li>
</ul>
<p><code>kill</code> 명령어의 기본 시그널은 <strong>SIGTERM(15)</strong> 입니다.<br>
이는 강제 종료가 아니라 정상 종료를 요청하는 신호입니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash"><span class="hljs-built_in">kill</span> PID
<span class="hljs-built_in">kill</span> -19 PID
</code></pre></div></code></pre>
<p>정상 종료가 되지 않을 경우에만<br>
보다 강한 시그널을 고려하는 것이 일반적입니다.</p>
<hr>
<h2 id="포그라운드와-백그라운드-전환" tabindex="-1" data-src-line="135">포그라운드와 백그라운드 전환 <a class="header-anchor" href="#포그라운드와-백그라운드-전환" aria-hidden="true">#</a></h2>
<p>명령어 뒤에 <code>&amp;</code>를 붙이면 백그라운드에서 실행됩니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash"><span class="hljs-built_in">sleep</span> 10000 &amp;
</code></pre></div></code></pre>
<p>실행 중인 작업은 <code>jobs</code>로 확인할 수 있으며,<br>
필요에 따라 포그라운드와 백그라운드를 전환할 수 있습니다.</p>
<ul>
<li><code>fg</code> : 백그라운드 → 포그라운드</li>
<li><code>bg</code> : 정지 상태 → 백그라운드</li>
</ul>
<hr>
<h2 id="우선순위는-언제-조정할까요" tabindex="-1" data-src-line="151">우선순위는 언제 조정할까요? <a class="header-anchor" href="#우선순위는-언제-조정할까요" aria-hidden="true">#</a></h2>
<p>모든 프로세스가 동일한 중요도를 가지지는 않습니다.<br>
CPU 자원을 덜 사용하도록 조정해야 하는 경우가 있습니다.</p>
<p>이를 위해 <code>nice</code>, <code>renice</code> 명령어를 사용합니다.</p>
<ul>
<li>nice 값 범위 : <strong>-20 ~ 19</strong></li>
<li>기본값 : <strong>0</strong></li>
<li>값이 낮을수록 우선순위가 높습니다.</li>
</ul>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash"><span class="hljs-built_in">nice</span> -n 10 <span class="hljs-built_in">command</span>
renice -10 PID
</code></pre></div></code></pre>
<p>일반 사용자는 0~19 범위만 사용할 수 있으며,<br>
root 사용자만 전체 범위를 조정할 수 있습니다.</p>
<hr>
<h2 id="시스템-자원-상태-확인" tabindex="-1" data-src-line="172">시스템 자원 상태 확인 <a class="header-anchor" href="#시스템-자원-상태-확인" aria-hidden="true">#</a></h2>
<p>프로세스 상태는 CPU와 메모리 상태와 함께 확인해야 합니다.</p>
<h3 id="cpu" tabindex="-1" data-src-line="176">CPU <a class="header-anchor" href="#cpu" aria-hidden="true">#</a></h3>
<ul>
<li><code>/proc/cpuinfo</code></li>
<li><code>iostat -c</code></li>
<li><code>mpstat</code></li>
</ul>
<h3 id="메모리" tabindex="-1" data-src-line="182">메모리 <a class="header-anchor" href="#메모리" aria-hidden="true">#</a></h3>
<ul>
<li><code>free</code></li>
<li><code>vmstat</code></li>
<li><code>/proc/meminfo</code></li>
<li><code>/proc/swaps</code></li>
</ul>
<p>자원 사용량을 함께 확인해야<br>
프로세스 문제를 정확히 판단할 수 있습니다.</p>
<hr>
<h2 id="프로세스-문제를-만났을-때의-기본-흐름" tabindex="-1" data-src-line="194">프로세스 문제를 만났을 때의 기본 흐름 <a class="header-anchor" href="#프로세스-문제를-만났을-때의-기본-흐름" aria-hidden="true">#</a></h2>
<ol>
<li>시스템이 느려졌다면 <code>top</code>으로 자원 사용 현황을 확인합니다.</li>
<li>원인이 되는 프로세스를 찾으면 <code>ps</code>로 PID와 부모 프로세스를 확인합니다.</li>
<li>정상 종료가 가능하다면 SIGTERM을 먼저 전달합니다.</li>
<li>반복 생성된다면 부모 프로세스나 서비스 관리 방식을 확인합니다.</li>
</ol>
<hr>
<p>프로세스 관리는 명령어를 외우는 영역이라기보다,<br>
시스템의 상태를 읽고 판단하는 과정에 가깝습니다.</p>
