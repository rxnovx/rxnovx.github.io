<h2 id="들어가기" tabindex="-1" data-src-line="4">들어가기 <a class="header-anchor" href="#들어가기" aria-hidden="true">#</a></h2>
<p>리눅스를 운영하다 보면, 디스크 하나로는 부족해지는 순간이 옵니다.<br>
서버가 여러 대로 늘어나거나, 사용자 홈 디렉토리를 중앙에서 관리해야 할 때가 그렇습니다.<br>
이때 자연스럽게 등장하는 개념이 <strong>네트워크 스토리지</strong>입니다.</p>
<p>이번 글에서는 네트워크 스토리지의 큰 그림을 먼저 짚고,<br>
그중에서도 <strong>NFS(Network File System)</strong> 를 중심으로 실제 설정과 동작 방식을 정리해보려 합니다.<br>
명령어 나열보다는, <em>왜 이렇게 동작하는지</em>를 이해하는 쪽에 초점을 두었습니다.</p>
<hr>
<h2 id="스토리지의-분류-das--nas--san" tabindex="-1" data-src-line="16">스토리지의 분류: DAS · NAS · SAN <a class="header-anchor" href="#스토리지의-분류-das--nas--san" aria-hidden="true">#</a></h2>
<p>스토리지는 접근 방식에 따라 크게 세 가지로 나뉩니다.</p>
<h3 id="das-direct-attached-storage" tabindex="-1" data-src-line="20">DAS (Direct Attached Storage) <a class="header-anchor" href="#das-direct-attached-storage" aria-hidden="true">#</a></h3>
<p>서버에 직접 연결된 스토리지입니다.<br>
내부 디스크, USB 외장 디스크가 여기에 해당합니다.</p>
<ul>
<li>장점: 단순함, 성능 예측이 쉬움</li>
<li>단점: 다른 서버와 공유 불가</li>
</ul>
<h3 id="nas-network-attached-storage" tabindex="-1" data-src-line="28">NAS (Network Attached Storage) <a class="header-anchor" href="#nas-network-attached-storage" aria-hidden="true">#</a></h3>
<p>네트워크를 통해 <strong>파일 단위</strong>로 접근하는 스토리지입니다.<br>
연결하면 바로 디렉토리와 파일이 보입니다.</p>
<ul>
<li>
<p>대표 프로토콜</p>
<ul>
<li>NFS (Unix/Linux 계열)</li>
<li>CIFS / SMB (Windows 계열)</li>
</ul>
</li>
</ul>
<h3 id="san-storage-area-network" tabindex="-1" data-src-line="38">SAN (Storage Area Network) <a class="header-anchor" href="#san-storage-area-network" aria-hidden="true">#</a></h3>
<p>네트워크를 통해 <strong>블록 단위</strong>로 접근하는 스토리지입니다.<br>
연결하면 디스크 하나가 새로 생긴 것처럼 보입니다.</p>
<ul>
<li>
<p>대표 기술</p>
<ul>
<li>
<p>FC-SAN (Fiber Channel)</p>
</li>
<li>
<p>IP-SAN</p>
<ul>
<li>FCoE</li>
<li>iSCSI</li>
</ul>
</li>
</ul>
</li>
</ul>
<h3 id="nas와-san의-핵심-차이" tabindex="-1" data-src-line="51">NAS와 SAN의 핵심 차이 <a class="header-anchor" href="#nas와-san의-핵심-차이" aria-hidden="true">#</a></h3>
<p>구분 기준은 단순합니다.</p>
<ul>
<li><strong>NAS</strong>: 파일 단위 전송</li>
<li><strong>SAN</strong>: 블록 단위 전송</li>
</ul>
<p>NAS는 파일 서버에 가깝고,<br>
SAN은 원격 디스크에 가깝다고 이해하시면 됩니다.</p>
<hr>
<h2 id="nfs란-무엇인가" tabindex="-1" data-src-line="63">NFS란 무엇인가 <a class="header-anchor" href="#nfs란-무엇인가" aria-hidden="true">#</a></h2>
<p>NFS는 전통적인 Unix 계열에서 사용해온 <strong>네트워크 파일 공유 방식</strong>입니다.<br>
로컬 디렉토리를 사용하는 것처럼 원격 파일 시스템을 다룰 수 있다는 점이 핵심입니다.</p>
<hr>
<h2 id="nfs-버전별-특징" tabindex="-1" data-src-line="70">NFS 버전별 특징 <a class="header-anchor" href="#nfs-버전별-특징" aria-hidden="true">#</a></h2>
<h3 id="nfs-v1--v2" tabindex="-1" data-src-line="72">NFS v1 / v2 <a class="header-anchor" href="#nfs-v1--v2" aria-hidden="true">#</a></h3>
<ul>
<li>UDP 기반 통신</li>
<li>LAN 환경을 전제로 설계</li>
<li>현재는 거의 사용되지 않음</li>
</ul>
<h3 id="nfs-v3" tabindex="-1" data-src-line="78">NFS v3 <a class="header-anchor" href="#nfs-v3" aria-hidden="true">#</a></h3>
<ul>
<li>TCP/IP 기반으로 전환</li>
<li>2GB 이상의 파일 지원</li>
<li>성능은 개선되었지만 보안 개념은 여전히 부족</li>
</ul>
<h3 id="nfs-v4" tabindex="-1" data-src-line="84">NFS v4 <a class="header-anchor" href="#nfs-v4" aria-hidden="true">#</a></h3>
<ul>
<li>TCP 2049 포트 단일화</li>
<li>상태 기반(Stateful) 프로토콜</li>
<li>가상 파일 시스템 개념 도입</li>
<li>인증 기반 접근 제어 지원</li>
</ul>
<p>현재 실무에서는 <strong>NFS v4</strong>가 기본 선택지입니다.</p>
<hr>
<h2 id="실습-환경-구성" tabindex="-1" data-src-line="95">실습 환경 구성 <a class="header-anchor" href="#실습-환경-구성" aria-hidden="true">#</a></h2>
<ul>
<li>vm1 : NFS Client</li>
<li>vm2 : NFS Server</li>
</ul>
<p>실습은 내부 네트워크 환경을 가정합니다.</p>
