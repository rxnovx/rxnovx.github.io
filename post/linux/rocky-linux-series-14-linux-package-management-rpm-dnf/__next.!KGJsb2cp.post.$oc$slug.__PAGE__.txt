<h2 id="들어가기" tabindex="-1" data-src-line="4">들어가기 <a class="header-anchor" href="#들어가기" aria-hidden="true">#</a></h2>
<p>예전의 리눅스 환경에서는 프로그램을 사용하려면 소스 코드를 직접 내려받아 컴파일하는 과정이 일반적이었습니다.<br>
이 방식은 유연하고 강력했지만, 컴파일 환경을 갖추기 어렵거나 빌드 과정 자체가 부담이 되는 사용자에게는 진입 장벽이 높았습니다.</p>
<p>이러한 불편함을 줄이기 위해 <strong>미리 컴파일된 형태의 프로그램을 배포</strong>하기 시작했고, 그 결과 등장한 개념이 바로 **패키지(package)**와 <strong>패키지 매니저(package manager)</strong> 입니다.</p>
<p>이번 글에서는 리눅스 패키징의 흐름을 간단히 살펴본 뒤, RPM 기반 시스템에서 사용하는 패키지 관리 방식과 <code>rpm</code>, <code>dnf</code> 명령어, 그리고 저장소(repository)의 개념까지 정리해보겠습니다.</p>
<hr>
<h2 id="소프트웨어-패키지-매니저의-등장-배경" tabindex="-1" data-src-line="15">소프트웨어 패키지 매니저의 등장 배경 <a class="header-anchor" href="#소프트웨어-패키지-매니저의-등장-배경" aria-hidden="true">#</a></h2>
<p>패키지는 단순히 실행 파일 하나만을 의미하지 않습니다.<br>
프로그램 실행에 필요한 라이브러리, 설정 파일, 문서, 스크립트 등을 하나의 묶음으로 관리하는 단위입니다.</p>
<p>패키지 매니저는 다음과 같은 문제를 해결하기 위해 등장했습니다.</p>
<ul>
<li>소프트웨어 설치 과정을 표준화하기 위해</li>
<li>파일이 어디에 설치되었는지 추적하기 위해</li>
<li>업데이트와 삭제를 안전하게 수행하기 위해</li>
<li>의존성 관계를 관리하기 위해</li>
</ul>
<p>이러한 요구가 쌓이면서 각 운영체제 계열마다 고유한 패키징 시스템이 발전하게 되었습니다.</p>
<hr>
<h2 id="유닉스와-리눅스의-패키징-계열" tabindex="-1" data-src-line="31">유닉스와 리눅스의 패키징 계열 <a class="header-anchor" href="#유닉스와-리눅스의-패키징-계열" aria-hidden="true">#</a></h2>
<h3 id="unix-계열" tabindex="-1" data-src-line="33">Unix 계열 <a class="header-anchor" href="#unix-계열" aria-hidden="true">#</a></h3>
<ul>
<li><strong>SysV packages</strong><br>
전통적인 UNIX System V 계열에서 사용되던 패키지 형식입니다.<br>
의존성 관리가 체계적이지 않아, 관리자가 설치 순서와 필요 파일을 직접 파악해야 하는 경우가 많았습니다.</li>
</ul>
<h3 id="linux-계열" tabindex="-1" data-src-line="39">Linux 계열 <a class="header-anchor" href="#linux-계열" aria-hidden="true">#</a></h3>
<p>리눅스는 배포판마다 패키징 정책이 다르며, 이 차이가 배포판의 성격을 결정하기도 합니다.</p>
<h4 id="slackware" tabindex="-1" data-src-line="43">Slackware <a class="header-anchor" href="#slackware" aria-hidden="true">#</a></h4>
<ul>
<li><strong>Slackware Tarballs</strong></li>
<li><code>tar</code> 기반의 단순한 패키지 형식</li>
<li>의존성 자동 해결 기능 없음</li>
</ul>
<p>관리자가 패키지 구조를 명확히 이해하고 직접 제어하는 방식을 취합니다.<br>
자동화보다는 단순성과 투명성을 중시하는 배포판입니다.</p>
<h4 id="debian-계열" tabindex="-1" data-src-line="52">Debian 계열 <a class="header-anchor" href="#debian-계열" aria-hidden="true">#</a></h4>
<ul>
<li>
<p><strong>Debian</strong></p>
<ul>
<li><code>dpkg</code>를 기본 패키지 도구로 사용</li>
<li><code>apt</code>를 통해 의존성 자동 해결과 저장소 기반 설치 제공</li>
</ul>
</li>
<li>
<p><strong>Ubuntu</strong></p>
<ul>
<li>Debian 기반</li>
<li>서버와 데스크톱 환경 모두를 고려한 사용자 친화적 패키징</li>
</ul>
</li>
<li>
<p><strong>Linux Mint</strong></p>
<ul>
<li>Ubuntu 기반</li>
<li>안정성과 사용 편의성을 강조</li>
</ul>
</li>
</ul>
<h4 id="red-hat-계열" tabindex="-1" data-src-line="69">Red Hat 계열 <a class="header-anchor" href="#red-hat-계열" aria-hidden="true">#</a></h4>
<ul>
<li>
<p><strong>Red Hat Enterprise Linux / Fedora / CentOS / Rocky Linux</strong></p>
<ul>
<li>RPM 포맷 사용</li>
<li><code>dnf</code> (과거 <code>yum</code>)을 통해 패키지 관리</li>
</ul>
</li>
<li>
<p><strong>SUSE Linux Enterprise</strong></p>
<ul>
<li>RPM 기반</li>
<li><code>zypper</code> 패키지 매니저 사용</li>
</ul>
</li>
<li>
<p><strong>Mandriva</strong></p>
<ul>
<li>RPM 기반 배포판</li>
<li>현재는 역사적 의미를 가지는 배포판</li>
</ul>
</li>
</ul>

<h3 id="네이밍-규칙" tabindex="-1" data-src-line="90">네이밍 규칙 <a class="header-anchor" href="#네이밍-규칙" aria-hidden="true">#</a></h3>

</ul>

<h3 id="아키텍처-구분" tabindex="-1" data-src-line="107">아키텍처 구분 <a class="header-anchor" href="#아키텍처-구분" aria-hidden="true">#</a></h3>
<ul>
<li>
<p><strong>.src.rpm</strong></p>
<ul>
<li>소스 코드와 spec 파일을 포함</li>
<li>바이너리 RPM을 생성하기 위한 재료</li>
</ul>
</li>
<li>
<p><strong>.noarch.rpm</strong></p>
<ul>
<li>CPU 아키텍처에 의존하지 않음</li>
<li>스크립트, 설정 파일, 인터프리터 언어 패키지에 주로 사용</li>
</ul>
</li>
<li>
<p><strong>.x86_64.rpm</strong></p>
<ul>
<li>64비트 x86 아키텍처용 바이너리 패키지</li>
</ul>
</li>
<li>
<p><strong>.i586.rpm</strong></p>
<ul>
<li>32비트 x86 계열 바이너리 패키지</li>
</ul>
</li>
<li>
<p><em><em>.arm</em>.rpm</em>*</p>
<ul>
<li>ARM 계열 CPU용 바이너리 패키지</li>
</ul>
</li>
</ul>
<hr>
<h3 id="내부-포맷" tabindex="-1" data-src-line="133">내부 포맷 <a class="header-anchor" href="#내부-포맷" aria-hidden="true">#</a></h3>
<p>RPM 파일은 다음 두 요소로 구성됩니다.</p>
<ul>
<li>
<p>바이너리 헤더</p>
<ul>
<li>메타데이터</li>
<li>의존성 정보</li>
</ul>
</li>
<li>
<p>실제 파일 데이터</p>
<ul>
<li><code>cpio</code> 아카이브 형식으로 저장</li>
</ul>
</li>
</ul>
<p>즉, RPM은 단순한 압축 파일이 아니라 <strong>패키지 관리에 필요한 정보를 함께 담은 구조</strong>입니다.</p>
<hr>
<h2 id="rpm-명령어로-패키지-상태-확인하기" tabindex="-1" data-src-line="150">rpm 명령어로 패키지 상태 확인하기 <a class="header-anchor" href="#rpm-명령어로-패키지-상태-확인하기" aria-hidden="true">#</a></h2>
<p>RPM은 저수준(low-level) 패키지 관리 도구입니다.<br>
의존성을 자동으로 해결하지는 않지만, 설치 상태를 정확히 조회하는 데 매우 유용합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">rpm -qa                <span class="hljs-comment"># 설치된 전체 패키지 목록</span>
rpm -ql package_name   <span class="hljs-comment"># 특정 패키지가 설치한 파일 목록</span>
rpm -qf /usr/bin/ls    <span class="hljs-comment"># 해당 파일을 제공하는 패키지 확인</span>
</code></pre></div></code></pre>
<p>실무에서는 <code>rpm -qa | grep 패키지명</code> 형태로 자주 사용합니다.</p>
<hr>
<h2 id="패키지를-직접-내려받아-설치해보기" tabindex="-1" data-src-line="165">패키지를 직접 내려받아 설치해보기 <a class="header-anchor" href="#패키지를-직접-내려받아-설치해보기" aria-hidden="true">#</a></h2>
<p>공식 저장소를 사용하지 않고, RPM 파일을 직접 설치할 수도 있습니다.</p>
<p>예를 들어 <code>rpmfind.net</code> 사이트에서 패키지를 검색한 뒤 다음과 같이 설치할 수 있습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">wget https://rpmfind.net/linux/centos-stream/10-stream/BaseOS/x86_64/os/Packages/zsh-5.9-15.el10.x86_64.rpm
wget https://rpmfind.net/linux/centos-stream/10-stream/AppStream/x86_64/os/Packages/git-2.52.0-1.el10.x86_64.rpm

rpm -Uvh zsh-5.9-15.el10.x86_64.rpm
rpm -Uvh git-2.52.0-1.el10.x86_64.rpm
</code></pre></div></code></pre>
<ul>
<li><code>-U</code> : 업그레이드 또는 신규 설치</li>
<li><code>-v</code> : 상세 출력</li>
<li><code>-h</code> : 진행 상황 표시</li>
</ul>
<p>이 방식의 단점은 <strong>의존성 패키지를 직접 해결해야 한다는 점</strong>입니다.<br>
이 불편함을 해결하기 위해 등장한 것이 <code>yum</code>과 <code>dnf</code>입니다.</p>
<hr>
<h2 id="rpm-패키지-삭제" tabindex="-1" data-src-line="188">rpm 패키지 삭제 <a class="header-anchor" href="#rpm-패키지-삭제" aria-hidden="true">#</a></h2>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">rpm -e 패키지명
</code></pre></div></code></pre>
<p>의존성 검사는 수행하지 않으므로, 시스템 패키지를 제거할 때는 주의가 필요합니다.</p>
<hr>
<h2 id="의존성-문제와-패키지-매니저의-역할" tabindex="-1" data-src-line="198">의존성 문제와 패키지 매니저의 역할 <a class="header-anchor" href="#의존성-문제와-패키지-매니저의-역할" aria-hidden="true">#</a></h2>
<p>RPM 자체는 의존성을 기록하지만, 자동으로 해결해주지는 않습니다.<br>
이 문제를 해결하기 위해 등장한 고수준(high-level) 도구가 바로 <strong>yum / dnf</strong> 입니다.</p>
<p>이 도구들은 다음을 담당합니다.</p>
<ul>
<li>의존성 자동 해결</li>
<li>저장소(repository) 기반 패키지 관리</li>
<li>업데이트 이력 관리</li>
</ul>
<hr>
<h2 id="yum--dnf-주요-명령어" tabindex="-1" data-src-line="211">YUM &amp; DNF 주요 명령어 <a class="header-anchor" href="#yum--dnf-주요-명령어" aria-hidden="true">#</a></h2>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">dnf search keyword        <span class="hljs-comment"># 패키지 검색</span>
dnf install package       <span class="hljs-comment"># 설치 또는 업데이트</span>
dnf remove package        <span class="hljs-comment"># 제거</span>
dnf repolist              <span class="hljs-comment"># 활성화된 저장소 목록</span>
dnf grouplist             <span class="hljs-comment"># 패키지 그룹 목록</span>
dnf groupinstall <span class="hljs-string">&quot;Group&quot;</span>  <span class="hljs-comment"># 그룹 설치</span>
dnf <span class="hljs-built_in">history</span>               <span class="hljs-comment"># 트랜잭션 이력</span>
dnf <span class="hljs-built_in">history</span> info 13       <span class="hljs-comment"># 특정 트랜잭션 상세</span>
dnf undo 13               <span class="hljs-comment"># 트랜잭션 되돌리기</span>
</code></pre></div></code></pre>
<p><code>dnf history</code> 기능은 시스템 변경 이력을 추적할 수 있어 운영 환경에서 특히 중요합니다.</p>
<hr>
<h2 id="repository-개념-이해하기" tabindex="-1" data-src-line="229">Repository 개념 이해하기 <a class="header-anchor" href="#repository-개념-이해하기" aria-hidden="true">#</a></h2>
<p>Repository는 <strong>패키지를 모아둔 저장소</strong>입니다.<br>
<code>dnf</code>는 이 저장소 정보를 기반으로 패키지를 검색하고 내려받습니다.</p>
<h3 id="저장소-설정-파일-예시" tabindex="-1" data-src-line="234">저장소 설정 파일 예시 <a class="header-anchor" href="#저장소-설정-파일-예시" aria-hidden="true">#</a></h3>
<p><code>/etc/yum.repos.d/rocky.repo</code></p>
<pre><code class="language-ini"><div class="code-block"><div class="code-header"><span class="code-title">ini</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-ini"><code class="hljs language-ini"><span class="hljs-section">[appstream]</span>

<hr>
<h2 id="epel-저장소" tabindex="-1" data-src-line="252">EPEL 저장소 <a class="header-anchor" href="#epel-저장소" aria-hidden="true">#</a></h2>
<p>EPEL(Extra Packages for Enterprise Linux)은 RHEL 계열에서 기본 저장소에 포함되지 않은 패키지를 제공합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">dnf install https://dl.fedoraproject.org/pub/epel/epel-release-latest-10.noarch.rpm
</code></pre></div></code></pre>
<p>서버 환경에서 자주 사용하는 유틸리티들이 다수 포함되어 있습니다.</p>
<hr>
<h2 id="폐쇄망-환경에서-repository-구성하기" tabindex="-1" data-src-line="264">폐쇄망 환경에서 Repository 구성하기 <a class="header-anchor" href="#폐쇄망-환경에서-repository-구성하기" aria-hidden="true">#</a></h2>
<p>외부 인터넷이 차단된 환경에서는 자체 저장소 구성이 필요합니다.</p>
<h3 id="기본-흐름" tabindex="-1" data-src-line="268">기본 흐름 <a class="header-anchor" href="#기본-흐름" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash"><span class="hljs-built_in">cp</span> *.rpm /src/repository
createrepo /src/repository
</code></pre></div></code></pre>
<p><code>createrepo</code>는 RPM 메타데이터를 생성하여 저장소로 인식할 수 있게 합니다.</p>
<h3 id="저장소-등록" tabindex="-1" data-src-line="277">저장소 등록 <a class="header-anchor" href="#저장소-등록" aria-hidden="true">#</a></h3>

</code></pre></div></code></pre>
<pre><code class="language-ini"><div class="code-block"><div class="code-header"><span class="code-title">ini</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-ini"><code class="hljs language-ini"><span class="hljs-section">[server1.example.com_RHEL8]</span>

</code></pre></div></code></pre>
<p>이 방식은 폐쇄망, 내부 테스트 환경, 보안망 구성 시 자주 사용됩니다.</p>
