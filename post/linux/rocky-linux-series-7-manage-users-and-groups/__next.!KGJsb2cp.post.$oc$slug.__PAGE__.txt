3:T441b,<h1 id="리눅스-배우기-7--로컬-유저와-그룹-관리" tabindex="-1" data-src-line="0">리눅스 배우기 #7 – 로컬 유저와 그룹 관리 <a class="header-anchor" href="#리눅스-배우기-7--로컬-유저와-그룹-관리" aria-hidden="true">#</a></h1>
<hr>
<h2 id="들어가기" tabindex="-1" data-src-line="4">들어가기 <a class="header-anchor" href="#들어가기" aria-hidden="true">#</a></h2>
<p>리눅스 시스템을 사용하려면 반드시 계정이 필요합니다.<br>
모든 로그인, 모든 작업은 결국 <strong>유저(user)</strong> 단위로 기록되고 제어됩니다.</p>
<p>이때 유저를 직접 하나하나 관리하기보다는,<br>
<strong>그룹을 먼저 만들고 그 그룹에 유저를 소속시키는 방식</strong>이 훨씬 효율적입니다.<br>
권한 관리 측면에서도 그렇고,<br>
실제 운영 환경에서도 이 방식이 기본이 됩니다.</p>
<p>개인적으로는 <strong>유저 관리보다 그룹 관리가 더 중요하고, 더 단순하다</strong>고 느끼는 편입니다.<br>
이 글에서는 그 흐름에 맞춰 그룹 → 유저 순서로 정리합니다.</p>
<hr>
<h2 id="group" tabindex="-1" data-src-line="19">GROUP <a class="header-anchor" href="#group" aria-hidden="true">#</a></h2>
<p>리눅스의 그룹 정보는 <code>/etc/group</code> 파일에 저장되어 있습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-built_in">cat</span> /etc/group
</code></pre></div></code></pre>
<p>이 파일은 한 줄이 하나의 그룹을 의미하며,<br>
각 줄은 <code>:</code> 기준으로 <strong>4개의 컬럼</strong>으로 구성됩니다.</p>
<ul>
<li>그룹 이름</li>
<li>그룹 비밀번호 (실제 사용하지 않음)</li>
<li>GID (Group ID)</li>
<li>그룹 구성원 목록</li>
</ul>
<p>형식은 아래와 같습니다.</p>
<pre><code class="language-text"><div class="code-block"><div class="code-header"><span class="code-title">text</span><button class="copy-button">Copy</button></div><pre class="language-text"><code>group_name:<span class="hljs-attribute">x</span>:<span class="hljs-attribute">GID</span>:user1,user2,user3
</code></pre></div></code></pre>
<hr>
<h3 id="groupadd--그룹-생성" tabindex="-1" data-src-line="43">groupadd : 그룹 생성 <a class="header-anchor" href="#groupadd--그룹-생성" aria-hidden="true">#</a></h3>
<p>새로운 그룹을 생성할 때 사용하는 명령어입니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># sales라는 그룹을 생성</span>
<span class="hljs-attribute">groupadd</span> sales

<span class="hljs-comment"># fin 이라는 그룹을 생성하고 GID를 2000으로 설정</span>
<span class="hljs-attribute">groupadd</span> -g <span class="hljs-number">2000</span> fin
</code></pre></div></code></pre>
<p>일반적으로 GID는 자동으로 할당되지만,<br>
조직 정책이나 기존 시스템과의 연계를 위해<br>
직접 지정해야 하는 경우도 종종 있습니다.</p>
<hr>
<h3 id="groupmod--그룹-설정-변경" tabindex="-1" data-src-line="61">groupmod : 그룹 설정 변경 <a class="header-anchor" href="#groupmod--그룹-설정-변경" aria-hidden="true">#</a></h3>
<p>이미 존재하는 그룹의 설정을 변경할 때 사용합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># sales 그룹의 GID를 3000으로 수정</span>
<span class="hljs-attribute">groupmod</span> -g <span class="hljs-number">3000</span> sales

<span class="hljs-comment"># fin 그룹의 이름을 oper로 변경</span>
<span class="hljs-attribute">groupmod</span> -n oper fin
</code></pre></div></code></pre>
<p>운영 중인 시스템에서는<br>
<strong>이미 사용 중인 GID를 변경하는 작업은 매우 신중해야 합니다.</strong><br>
파일 소유권과 직접적으로 연결되기 때문입니다.</p>
<hr>
<h3 id="groupdel--그룹-삭제" tabindex="-1" data-src-line="79">groupdel : 그룹 삭제 <a class="header-anchor" href="#groupdel--그룹-삭제" aria-hidden="true">#</a></h3>
<p>그룹을 삭제할 때 사용합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># oper 그룹을 삭제</span>
<span class="hljs-attribute">groupdel</span> oper
</code></pre></div></code></pre>
<p>해당 그룹을 primary 그룹으로 사용하는 유저가 있다면 삭제되지 않습니다.<br>
이 경우 먼저 유저의 그룹을 변경해야 합니다.</p>
<hr>
<h2 id="user" tabindex="-1" data-src-line="93">USER <a class="header-anchor" href="#user" aria-hidden="true">#</a></h2>
<p>유저 관련 정보는 여러 파일에 나뉘어 관리됩니다.</p>
<ul>
<li><code>/etc/passwd</code> : 계정 기본 정보</li>
<li><code>/etc/shadow</code> : 암호 및 만료 정책</li>
<li><code>/etc/shells</code> : 로그인 가능한 쉘 목록</li>
</ul>
<p><code>/etc/passwd</code>의 한 줄은 다음과 같은 구조를 가집니다.</p>
<pre><code class="language-text"><div class="code-block"><div class="code-header"><span class="code-title">text</span><button class="copy-button">Copy</button></div><pre class="language-text"><code>계정명<span class="hljs-symbol">:</span>암호<span class="hljs-symbol">:UID</span><span class="hljs-symbol">:GID</span><span class="hljs-symbol">:</span>유저메모<span class="hljs-symbol">:</span>홈디렉토리<span class="hljs-symbol">:</span>로그인쉘
</code></pre></div></code></pre>
<p>실제 암호는 <code>/etc/shadow</code> 파일에 해시 형태로 저장됩니다.</p>
<hr>
<h3 id="useradd--유저-생성" tabindex="-1" data-src-line="111">useradd : 유저 생성 <a class="header-anchor" href="#useradd--유저-생성" aria-hidden="true">#</a></h3>
<p>새로운 계정을 생성하는 명령어입니다.</p>
<p>주요 옵션은 다음과 같습니다.</p>
<ul>
<li><code>-u</code> : UID 지정</li>
<li><code>-c</code> : 유저 메모(Comment)</li>
<li><code>-r</code> : 시스템 계정 생성 (UID 1~999)</li>
<li><code>-s</code> : 로그인 쉘 지정</li>
<li><code>-g</code> : primary 그룹 지정</li>
<li><code>-G</code> : secondary 그룹 지정</li>
<li><code>-m</code> : 홈 디렉토리 생성</li>
<li><code>-d</code> : 홈 디렉토리 경로 지정</li>
</ul>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># tom 이라는 계정을 생성</span>
useradd tom

<span class="hljs-comment"># user1을 생성하고 UID를 3001, 메모를 &quot;New User&quot;로 설정</span>
useradd -u 3001 -c <span class="hljs-string">&quot;New User&quot;</span> user1

<span class="hljs-comment"># 시스템 계정 derek 생성</span>
useradd -r -s /sbin/nologin -g sys -G sup1 derek

useradd -u 4989 -s /bin/csh -c <span class="hljs-string">&quot;010-1111-2222&quot;</span> susan
useradd -r -s /sbin/nologin -g sales -G sshd,kvm,dbus -m -d /oracle ora
</code></pre></div></code></pre>
<p>리눅스에는 <strong>primary 그룹과 secondary 그룹</strong> 개념이 있습니다.</p>
<ul>
<li><code>-g</code> : primary 그룹 (기본 소유 그룹)</li>
<li><code>-G</code> : secondary 그룹 (추가 소속 그룹)</li>
</ul>
<p>파일 권한과 접근 제어를 이해하려면<br>
이 구분은 반드시 알고 있어야 합니다.</p>
<hr>
<h3 id="usermod--유저-설정-변경" tabindex="-1" data-src-line="150">usermod : 유저 설정 변경 <a class="header-anchor" href="#usermod--유저-설정-변경" aria-hidden="true">#</a></h3>
<p>이미 존재하는 유저의 설정을 변경할 때 사용합니다.</p>
<p><code>useradd</code>에서 사용하던 옵션 대부분을 그대로 사용할 수 있습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># susan의 UID를 3030으로 변경하고</span>
<span class="hljs-comment"># primary 그룹을 sales로, 로그인 쉘을 bash로 변경</span>
<span class="hljs-attribute">usermod</span> -u <span class="hljs-number">3030</span> -g sales -s /bin/bash susan
</code></pre></div></code></pre>
<p>secondary 그룹을 추가할 때는 <code>-aG</code> 옵션을 사용합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># susan을 기존 그룹은 유지한 채 docker 그룹에 추가</span>
<span class="hljs-attribute">usermod</span> -aG docker susan
</code></pre></div></code></pre>
<p><code>-a</code> 옵션 없이 <code>-G</code>만 사용하면<br>
기존 secondary 그룹이 모두 사라지므로 주의해야 합니다.</p>
<hr>
<h3 id="userdel--유저-삭제" tabindex="-1" data-src-line="174">userdel : 유저 삭제 <a class="header-anchor" href="#userdel--유저-삭제" aria-hidden="true">#</a></h3>
<p>유저를 삭제할 때 사용하는 명령어입니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># tom은 홈디렉토리까지 삭제</span>
<span class="hljs-attribute">userdel</span> -r tom

<span class="hljs-comment"># susan은 계정만 삭제, 홈디렉토리는 유지</span>
userdel susan
</code></pre></div></code></pre>
<p>운영 환경에서는<br>
데이터 보존 여부를 반드시 확인한 후 삭제하는 것이 안전합니다.</p>
<hr>
<h3 id="특정-유저가-만든-파일-정리" tabindex="-1" data-src-line="191">특정 유저가 만든 파일 정리 <a class="header-anchor" href="#특정-유저가-만든-파일-정리" aria-hidden="true">#</a></h3>
<p>계정은 삭제했지만,<br>
파일 시스템에는 해당 UID를 가진 파일이 남아있는 경우가 많습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># UID 1701이 소유한 파일 및 디렉토리 삭제</span>
find / -uid 1701 -<span class="hljs-built_in">exec</span> <span class="hljs-built_in">rm</span> -rf {} +
</code></pre></div></code></pre>
<p>소유자가 없는 파일(<code>-nouser</code>)을 처리하는 예시는 아래와 같습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># 소유자가 없는 파일을 /tmp/backup 으로 이동</span>
<span class="hljs-built_in">mkdir</span> /tmp/backup
find / -nouser 2&gt; /dev/null -<span class="hljs-built_in">exec</span> <span class="hljs-built_in">mv</span> {} /tmp/backup \;
</code></pre></div></code></pre>
<p>이 작업은 반드시 신중하게 진행해야 합니다.</p>
<hr>
<h2 id="shadow-파일과-비밀번호-정책" tabindex="-1" data-src-line="213">Shadow 파일과 비밀번호 정책 <a class="header-anchor" href="#shadow-파일과-비밀번호-정책" aria-hidden="true">#</a></h2>
<p><code>/etc/shadow</code> 파일은<br>
유저의 비밀번호와 만료 정책을 관리하는 핵심 파일입니다.</p>
<p>이 파일을 직접 수정하기보다는<br>
<code>chage</code> 명령어를 사용하는 것이 일반적입니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-comment"># 현재 비밀번호/계정 만료 정책 확인</span>
chage -l <span class="hljs-keyword">user</span>

<span class="hljs-title"># 다음 로그인 시 비밀번호 변경 강제
chage</span> -d <span class="hljs-number">0</span> <span class="hljs-keyword">user</span>

<span class="hljs-title"># 비밀번호 최소 사용 기간 7</span>일
chage -m <span class="hljs-number">7</span> <span class="hljs-keyword">user</span>

<span class="hljs-title"># 비밀번호 최대 사용 기간 90</span>일
chage -M <span class="hljs-number">90</span> <span class="hljs-keyword">user</span>

<span class="hljs-title"># 만료 7</span>일 전 경고
chage -W <span class="hljs-number">7</span> <span class="hljs-keyword">user</span>

<span class="hljs-title"># 만료 후 14</span>일 지나면 계정 비활성화
chage -I <span class="hljs-number">14</span> <span class="hljs-keyword">user</span>

<span class="hljs-title"># 계정 만료일 설정
chage</span> -E <span class="hljs-number">2026</span>-<span class="hljs-number">12</span>-<span class="hljs-number">31</span> <span class="hljs-keyword">user</span>
<span class="hljs-title"></span></code></pre></div></code></pre>
<p>shadow 파일의 각 필드는 다음 의미를 가집니다.</p>
<pre><code class="language-text"><div class="code-block"><div class="code-header"><span class="code-title">text</span><button class="copy-button">Copy</button></div><pre class="language-text"><code>username:password:lastchg:<span class="hljs-built_in">min</span>:<span class="hljs-built_in">max</span>:warn:inactive:expire:reserved
</code></pre></div></code></pre>
<hr>
<h2 id="계정-생성-시-영향을-주는-설정-파일" tabindex="-1" data-src-line="252">계정 생성 시 영향을 주는 설정 파일 <a class="header-anchor" href="#계정-생성-시-영향을-주는-설정-파일" aria-hidden="true">#</a></h2>
<h3 id="etclogindefs" tabindex="-1" data-src-line="254">/etc/login.defs <a class="header-anchor" href="#etclogindefs" aria-hidden="true">#</a></h3>
<p>계정 관련 명령어의 <strong>기본 보안 정책</strong>을 정의합니다.</p>
<ul>
<li>login</li>
<li>useradd</li>
<li>passwd</li>
</ul>
<p>이 파일은 PAM보다 하위 레벨에서<br>
기본값의 기준이 됩니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-attribute">PASS_MAX_DAYS</span> <span class="hljs-number">60</span>
<span class="hljs-attribute">PASS_MIN_DAYS</span> <span class="hljs-number">10</span>
<span class="hljs-attribute">UID_MIN</span>       <span class="hljs-number">10000</span>
<span class="hljs-attribute">GID_MIN</span>       <span class="hljs-number">20000</span>
</code></pre></div></code></pre>
<hr>
<h3 id="etcdefaultuseradd" tabindex="-1" data-src-line="274">/etc/default/useradd <a class="header-anchor" href="#etcdefaultuseradd" aria-hidden="true">#</a></h3>
<p><code>useradd</code> 명령어를 실행할 때<br>
옵션을 주지 않으면 적용되는 기본값입니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-attribute">INACTIVE</span><span class="hljs-operator">=</span><span class="hljs-number">30</span>
</code></pre></div></code></pre>
<hr>
<h3 id="etcskel" tabindex="-1" data-src-line="285">/etc/skel <a class="header-anchor" href="#etcskel" aria-hidden="true">#</a></h3>
<p>새 계정을 생성할 때,<br>
<code>/etc/skel</code> 디렉토리 안의 파일과 디렉토리가<br>
사용자의 홈 디렉토리로 그대로 복사됩니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-built_in">mkdir</span> -p /etc/skel/Data
<span class="hljs-built_in">touch</span> /etc/skel/manual.txt

useradd lunch
passwd lunch
chage -l lunch
</code></pre></div></code></pre>
<p>초기 환경을 표준화할 때 매우 유용한 구조입니다.</p>
<hr>
<h2 id="마무리" tabindex="-1" data-src-line="304">마무리 <a class="header-anchor" href="#마무리" aria-hidden="true">#</a></h2>
<p>유저와 그룹 관리는<br>
리눅스 시스템 보안과 운영의 기본입니다.</p>
<p>명령어 자체는 단순하지만,<br>
그 결과는 파일 권한, 접근 제어, 로그 기록까지 모두 연결됩니다.</p>
<p>이번 내용은 이후에 다룰<br>
