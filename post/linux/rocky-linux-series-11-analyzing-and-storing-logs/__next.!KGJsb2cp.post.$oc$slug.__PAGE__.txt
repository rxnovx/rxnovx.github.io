<h2 id="들어가기" tabindex="-1" data-src-line="4">들어가기 <a class="header-anchor" href="#들어가기" aria-hidden="true">#</a></h2>
<p>리눅스를 사용하다 보면 반드시 마주치게 되는 것이 로그입니다.<br>
서비스가 왜 죽었는지, 인증이 왜 실패했는지, 시스템에 어떤 일이 있었는지를 가장 정확하게 말해주는 것이 로그입니다.<br>
이번 글에서는 리눅스에서 로그가 어떻게 관리되는지, 그리고 실제로 어떻게 확인하고 설정하는지를 정리해봅니다.</p>
<hr>
<h2 id="리눅스의-로그-관리-흐름" tabindex="-1" data-src-line="12">리눅스의 로그 관리 흐름 <a class="header-anchor" href="#리눅스의-로그-관리-흐름" aria-hidden="true">#</a></h2>
<p>리눅스의 로그 시스템은 한 번에 만들어진 것이 아니라, 시간이 지나며 점진적으로 발전해왔습니다.<br>
현재 기준으로는 다음 세 가지 흐름을 이해하면 정리가 됩니다.</p>
<h3 id="sysklogd" tabindex="-1" data-src-line="17">Sysklogd <a class="header-anchor" href="#sysklogd" aria-hidden="true">#</a></h3>
<p>Sysklogd는 전통적인 유닉스/리눅스 로그 관리 프로그램입니다.<br>
<code>syslogd</code>, <code>klogd</code>로 구성되어 있으며, 텍스트 파일 기반 로그 관리의 출발점이라고 볼 수 있습니다.<br>
최근 배포판에서는 거의 사용되지 않지만, rsyslog의 기반 개념을 이해하는 데 의미가 있습니다.</p>
<h3 id="rsyslog" tabindex="-1" data-src-line="23">Rsyslog <a class="header-anchor" href="#rsyslog" aria-hidden="true">#</a></h3>
<p>rsyslog는 Sysklogd를 대체하기 위해 등장한 로그 데몬입니다.<br>
RHEL 계열 기준으로 기본 로그 시스템으로 오랫동안 사용되어 왔습니다.</p>
<p>특징은 다음과 같습니다.</p>
<ul>
<li>원격 로그 전송 및 수신 가능</li>
<li>IPv4 / IPv6 모두 지원</li>
<li>조건 기반 필터링 및 파일 분리 저장 가능</li>
<li>기본적으로 텍스트 파일로 로그를 관리</li>
</ul>
<h3 id="systemd-journal" tabindex="-1" data-src-line="35">systemd Journal <a class="header-anchor" href="#systemd-journal" aria-hidden="true">#</a></h3>
<p>RHEL7부터 시스템 시작 프로세스가 init에서 systemd로 변경되면서, journald라는 로그 관리 시스템이 함께 도입되었습니다.<br>
기존 파일 기반 로그와 달리 바이너리 형태로 로그를 저장하며, 전용 도구를 통해서만 조회합니다.</p>
<hr>
<h2 id="systemd-journal의-특징" tabindex="-1" data-src-line="42">systemd Journal의 특징 <a class="header-anchor" href="#systemd-journal의-특징" aria-hidden="true">#</a></h2>
<h3 id="휘발성-로그-구조" tabindex="-1" data-src-line="44">휘발성 로그 구조 <a class="header-anchor" href="#휘발성-로그-구조" aria-hidden="true">#</a></h3>
<p>기본 설정에서 journal 로그는 휘발성입니다.<br>
시스템이 재부팅되면 로그가 사라집니다.</p>
<p>휘발성 로그는 다음 경로에 저장됩니다.</p>
<ul>
<li><code>/run/log/journal/&lt;machine-id&gt;/</code></li>
</ul>
<p>machine-id는 시스템을 식별하는 고유 값이며, <code>hostnamectl</code> 명령으로 확인할 수 있습니다.</p>
<h3 id="영구-로그로-전환하기" tabindex="-1" data-src-line="55">영구 로그로 전환하기 <a class="header-anchor" href="#영구-로그로-전환하기" aria-hidden="true">#</a></h3>
<p>로그를 재부팅 후에도 유지하고 싶다면 별도의 디렉토리를 생성해야 합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash"><span class="hljs-built_in">mkdir</span> -p /var/log/journal
</code></pre></div></code></pre>
<p>이 디렉토리가 존재하면 journald는 자동으로 로그를 영구 저장 모드로 전환합니다.<br>
최근 버전에서는 서비스 재시작 없이도 바로 적용됩니다.</p>
<hr>
<h2 id="journalctl-사용법" tabindex="-1" data-src-line="68">journalctl 사용법 <a class="header-anchor" href="#journalctl-사용법" aria-hidden="true">#</a></h2>
<p>journal 로그는 일반적인 <code>cat</code>이나 <code>ls</code>로 확인할 수 없습니다.<br>
바이너리 형식이기 때문에 전용 뷰어인 <code>journalctl</code>을 사용해야 합니다.</p>
<h3 id="기본-조회" tabindex="-1" data-src-line="73">기본 조회 <a class="header-anchor" href="#기본-조회" aria-hidden="true">#</a></h3>
<ul>
<li>기본 정렬은 오래된 로그가 위에 표시됩니다.</li>
<li>최신 로그부터 보고 싶다면 <code>-r</code> 옵션을 사용합니다.</li>
</ul>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">journalctl -r
</code></pre></div></code></pre>
<h3 id="줄-수-제한" tabindex="-1" data-src-line="82">줄 수 제한 <a class="header-anchor" href="#줄-수-제한" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">journalctl -n 50
</code></pre></div></code></pre>
<p>지정한 개수만큼의 로그만 출력합니다.</p>
<h3 id="실시간-로그-확인" tabindex="-1" data-src-line="90">실시간 로그 확인 <a class="header-anchor" href="#실시간-로그-확인" aria-hidden="true">#</a></h3>

<h3 id="priority-기반-필터링" tabindex="-1" data-src-line="98">Priority 기반 필터링 <a class="header-anchor" href="#priority-기반-필터링" aria-hidden="true">#</a></h3>

<h2 id="journal-로그-씰링sealing" tabindex="-1" data-src-line="136">Journal 로그 씰링(Sealing) <a class="header-anchor" href="#journal-로그-씰링sealing" aria-hidden="true">#</a></h2>
