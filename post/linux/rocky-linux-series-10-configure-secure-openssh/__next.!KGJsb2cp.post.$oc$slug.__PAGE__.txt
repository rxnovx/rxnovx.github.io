<p>SSH를 처음부터 적극적으로 사용해온 편은 아니었습니다.<br>
예전에는 원격 접속과 파일 전송을 위해 서로 다른 프로토콜을 사용하던 시기가 있었습니다.</p>
<p>당시 대표적으로 사용되던 방식은 다음과 같습니다.</p>
<div class="table-scroll" tabindex="0" role="region" aria-label="Scrollable table"><table>

</div><p>문제는 이 방식들이 모두 <strong>평문 통신</strong>을 사용했다는 점입니다.<br>
네트워크 중간에서 패킷을 가로채면, 사용자 계정과 비밀번호, 명령어 내용까지 그대로 노출되는 구조였습니다.<br>
보안이라는 개념이 지금만큼 중요하게 다뤄지기 전의 이야기입니다.</p>
<p>이러한 문제를 해결하기 위해 등장한 것이 <strong>SSH(Secure Shell)</strong> 입니다.<br>
SSH는 원격 접속과 파일 전송을 암호화된 채널 위에서 처리합니다.</p>
<ul>
<li>ssh : 원격 접속</li>
<li>scp : 파일 복사</li>
<li>sftp : 파일 전송</li>
</ul>
<p>하나의 패키지를 설치하면 위 세 가지 도구를 함께 사용할 수 있습니다.<br>
이 글에서는 OpenSSH 서비스의 구성과 기본적인 보안 설정 방법을 정리해봅니다.</p>
<hr>
<h2 id="ssh와-암호화-방식" tabindex="-1" data-src-line="30">SSH와 암호화 방식 <a class="header-anchor" href="#ssh와-암호화-방식" aria-hidden="true">#</a></h2>
<p>SSH는 통신 내용을 암호화하기 위해 <strong>키 기반 인증</strong>을 사용합니다.<br>
키를 사용하는 방식에는 크게 두 가지가 있습니다.</p>
<ul>
<li>대칭키 방식 (키 1개)</li>
<li>비대칭키 방식 (공개키 / 개인키 2개)</li>
</ul>
<p>SSH는 기본적으로 비대칭키 암호화를 사용합니다.<br>
처음 서버에 접속할 때 서버는 자신의 <strong>호스트 공개키</strong>를 클라이언트에게 전달합니다.<br>
클라이언트는 이를 known_hosts 파일에 저장하고, 이후부터는 해당 서버의 신원을 검증하는 데 사용합니다.</p>
<p>이 과정 덕분에 중간자 공격을 어느 정도 방어할 수 있습니다.</p>
<hr>

무한 대기 상태를 방지하기 위한 설정입니다.</p>

<h2 id="ssh-접속-방식" tabindex="-1" data-src-line="165">SSH 접속 방식 <a class="header-anchor" href="#ssh-접속-방식" aria-hidden="true">#</a></h2>

<h3 id="인터랙티브-로그인" tabindex="-1" data-src-line="169">인터랙티브 로그인 <a class="header-anchor" href="#인터랙티브-로그인" aria-hidden="true">#</a></h3>

</code></pre></div></code></pre>
<p>원격 시스템에 로그인하여 쉘을 사용하는 방식입니다.</p>
<h3 id="명령어-단일-실행" tabindex="-1" data-src-line="177">명령어 단일 실행 <a class="header-anchor" href="#명령어-단일-실행" aria-hidden="true">#</a></h3>

</code></pre></div></code></pre>

자동화 스크립트에서 자주 사용됩니다.</p>

<h2 id="파일-전송-방식" tabindex="-1" data-src-line="188">파일 전송 방식 <a class="header-anchor" href="#파일-전송-방식" aria-hidden="true">#</a></h2>
