<h2 id="들어가기" tabindex="-1" data-src-line="4">들어가기 <a class="header-anchor" href="#들어가기" aria-hidden="true">#</a></h2>
<p>리눅스를 사용하다 보면 결국 네트워크를 마주치게 됩니다.<br>
패키지가 안 내려받아질 때, SSH 접속이 안 될 때, 서비스는 살아 있는데 외부에서 접근이 안 될 때.<br>
대부분 네트워크 설정 문제입니다.</p>
<p>이번 글에서는 <strong>RHEL 계열 리눅스에서 네트워크를 관리하는 기본 흐름</strong>을 정리합니다.<br>
이론은 꼭 필요한 만큼만 다루고, 실제로 시스템에서 무엇을 확인하고 어떻게 설정하는지에 집중합니다.</p>
<hr>
<h2 id="ipv4-기초" tabindex="-1" data-src-line="15">IPv4 기초 <a class="header-anchor" href="#ipv4-기초" aria-hidden="true">#</a></h2>
<h3 id="ipv4-주소란" tabindex="-1" data-src-line="17">IPv4 주소란 <a class="header-anchor" href="#ipv4-주소란" aria-hidden="true">#</a></h3>
<p>IPv4 주소는 <strong>32비트 주소 체계</strong>입니다.<br>
총 개수는 약 43억 개이며, 다음 두 부분으로 나뉩니다.</p>
<ul>
<li>Network 부분</li>
<li>Host 부분</li>
</ul>
<p>일반적인 /24 네트워크에서는 마지막 옥텟이 호스트 영역입니다.<br>
이때 사용 가능한 호스트 번호는 <strong>1부터 254까지</strong>입니다.</p>
<h3 id="스페셜-주소" tabindex="-1" data-src-line="28">스페셜 주소 <a class="header-anchor" href="#스페셜-주소" aria-hidden="true">#</a></h3>
<p>IPv4에는 사용 목적이 정해진 주소가 있습니다.</p>
<ul>
<li>네트워크 주소: 호스트 비트가 모두 0</li>
<li>브로드캐스트 주소: 호스트 비트가 모두 1</li>
</ul>
<p>예를 들어 <code>192.168.1.0/24</code>에서</p>
<ul>
<li><code>192.168.1.0</code> → 네트워크 주소</li>
<li><code>192.168.1.255</code> → 브로드캐스트 주소</li>
</ul>
<p>이 두 주소는 <strong>호스트에 할당할 수 없습니다.</strong></p>
<h3 id="주소-클래스" tabindex="-1" data-src-line="42">주소 클래스 <a class="header-anchor" href="#주소-클래스" aria-hidden="true">#</a></h3>
<p>과거에는 주소를 클래스 단위로 나누어 사용했습니다.</p>
<ul>
<li>Class A / B / C</li>
</ul>
<p>현재는 거의 사용하지 않고, <strong>CIDR(Classless Inter-Domain Routing)</strong> 방식이 표준입니다.</p>
<ul>
<li><code>/8</code>, <code>/16</code>, <code>/24</code> 같은 프리픽스 길이로 네트워크를 표현합니다.</li>
</ul>
<hr>
<h2 id="사설-ip와-nat" tabindex="-1" data-src-line="54">사설 IP와 NAT <a class="header-anchor" href="#사설-ip와-nat" aria-hidden="true">#</a></h2>
<p>사설 IP는 인터넷에서 직접 라우팅되지 않는 주소입니다.<br>
RFC 1918에 정의되어 있으며 다음 세 대역이 있습니다.</p>
<ul>
<li><code>10.0.0.0/8</code></li>
<li><code>172.16.0.0/12</code></li>
<li><code>192.168.0.0/16</code></li>
</ul>
<p>사설 IP는 그대로 인터넷에 나갈 수 없기 때문에 <strong>NAT(Network Address Translation)</strong> 기술을 사용합니다.</p>
<h3 id="nat와-napt" tabindex="-1" data-src-line="65">NAT와 NAPT <a class="header-anchor" href="#nat와-napt" aria-hidden="true">#</a></h3>
<ul>
<li>NAT: 사설 IP ↔ 공인 IP 변환</li>
<li>NAPT: IP + 포트 번호까지 함께 변환</li>
</ul>
<p>가정용 공유기 환경에서 여러 장비가 하나의 공인 IP를 사용하는 이유가 바로 NAPT입니다.</p>

<h2 id="tcp--udp-기초" tabindex="-1" data-src-line="74">TCP / UDP 기초 <a class="header-anchor" href="#tcp--udp-기초" aria-hidden="true">#</a></h2>
<h3 id="tcp" tabindex="-1" data-src-line="76">TCP <a class="header-anchor" href="#tcp" aria-hidden="true">#</a></h3>
<ul>
<li>Connection-oriented</li>
<li>Reliable</li>
<li>순서 보장, 재전송, 흐름 제어</li>
<li>기본 헤더 크기: 20바이트</li>
</ul>
<p>대표적인 서비스:</p>
<ul>
<li>SSH</li>
<li>HTTP/HTTPS</li>
<li>FTP</li>
</ul>
<h3 id="udp" tabindex="-1" data-src-line="89">UDP <a class="header-anchor" href="#udp" aria-hidden="true">#</a></h3>
<ul>
<li>Connection-less</li>
<li>Stateless</li>
<li>Lightweight</li>
<li>기본 헤더 크기: 8바이트</li>
</ul>
<p>대표적인 서비스:</p>
<ul>
<li>DNS</li>
<li>DHCP</li>
<li>NTP</li>
</ul>
<h3 id="시스템-서비스-포트-정보" tabindex="-1" data-src-line="102">시스템 서비스 포트 정보 <a class="header-anchor" href="#시스템-서비스-포트-정보" aria-hidden="true">#</a></h3>

<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-built_in">cat</span> /etc/services

<h2 id="ipv6-개요" tabindex="-1" data-src-line="114">IPv6 개요 <a class="header-anchor" href="#ipv6-개요" aria-hidden="true">#</a></h2>
<p>IPv4는 주소 고갈 문제가 있습니다.<br>
IPv6는 이를 해결하기 위해 등장했습니다.</p>
<ul>
<li>IPv4: 32bit (약 43억 개)</li>
<li>IPv6: 128bit (사실상 고갈 걱정 없음)</li>
</ul>
<p>RHEL 계열 리눅스에서는 <strong>RHEL 8부터 IPv6가 기본 활성화</strong>되어 있습니다.</p>
<h3 id="ipv6-주소-예시" tabindex="-1" data-src-line="124">IPv6 주소 예시 <a class="header-anchor" href="#ipv6-주소-예시" aria-hidden="true">#</a></h3>
<ul>
<li><code>2001:db8::1/32</code></li>
<li><code>2001:0db8:0000:0000:0000:0000:0000:0001/32</code></li>
</ul>
<p>축약 표기(<code>::</code>)는 연속된 0을 줄여 쓴 것입니다.</p>

<h2 id="리눅스-네트워크-인터페이스-이름-규칙" tabindex="-1" data-src-line="133">리눅스 네트워크 인터페이스 이름 규칙 <a class="header-anchor" href="#리눅스-네트워크-인터페이스-이름-규칙" aria-hidden="true">#</a></h2>

<ul>
<li><code>eth0</code>, <code>eth1</code></li>
</ul>
<p>RHEL 7 이후부터는 <strong>예측 가능한 네이밍 규칙</strong>을 사용합니다.</p>
<h3 id="주요-접두어" tabindex="-1" data-src-line="141">주요 접두어 <a class="header-anchor" href="#주요-접두어" aria-hidden="true">#</a></h3>

<li><code>wl</code> : Wireless LAN</li>
<li><code>ww</code> : Wireless WAN</li>

<h3 id="ethernet-상세-규칙" tabindex="-1" data-src-line="147">Ethernet 상세 규칙 <a class="header-anchor" href="#ethernet-상세-규칙" aria-hidden="true">#</a></h3>
<ul>

<p>이름이 길어졌지만, <strong>하드웨어 위치를 추적하기는 훨씬 쉬워졌습니다.</strong></p>

<h2 id="ethtool-명령어" tabindex="-1" data-src-line="158">ethtool 명령어 <a class="header-anchor" href="#ethtool-명령어" aria-hidden="true">#</a></h2>
<p><code>ethtool</code>은 네트워크 카드의 <strong>물리 계층 정보</strong>를 확인하는 도구입니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button class="copy-button">Copy</button></div><pre class="language-bash"><code><span class="hljs-attribute">ethtool</span> ens160

<li>듀플렉스 모드 (Full / Half)</li>
<li>Auto-negotiation 상태</li>
<li>링크 연결 여부</li>
</ul>
<blockquote>
<p>Link detected: yes</p>
<p>→ 케이블 또는 가상 NIC 연결은 정상이라는 의미입니다.</p>
</blockquote>
<p>네트워크가 안 된다고 해서 항상 IP 문제는 아닙니다.<br>
