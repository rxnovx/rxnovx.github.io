<h2 id="들어가기" tabindex="-1" data-src-line="4">들어가기 <a class="header-anchor" href="#들어가기" aria-hidden="true">#</a></h2>
<p>리눅스를 사용하다 보면 디스크 용량이 부족해질 때가 있습니다.<br>
처음 설치할 때는 넉넉해 보이던 공간도 로그가 쌓이고, 데이터가 늘고, 서비스가 추가되면서 금방 한계에 도달합니다.</p>
<p>이때 가장 많이 쓰이는 기술이 <strong>LVM(Logical Volume Management)</strong> 입니다.<br>
LVM은 단순히 디스크를 묶는 도구가 아니라, <strong>디스크를 다루는 사고방식 자체를 바꿔주는 계층</strong>이라고 보는 편이 더 정확합니다.</p>
<p>이번 글에서는 명령어 암기보다는,<br>
디스크 → LVM → 파일시스템으로 이어지는 흐름과 내부 개념을 이해하는 데 초점을 두고 정리해보겠습니다.</p>
<hr>
<h2 id="lvm이-필요한-이유" tabindex="-1" data-src-line="17">LVM이 필요한 이유 <a class="header-anchor" href="#lvm이-필요한-이유" aria-hidden="true">#</a></h2>
<p>전통적인 파티션 기반 디스크 관리는 한계가 명확합니다.</p>
<ul>
<li>파티션 크기를 줄이기 어렵습니다.</li>
<li>디스크를 추가해도 기존 파티션을 바로 확장할 수 없습니다.</li>
<li>서비스 중단 없이 구조를 바꾸기 힘듭니다.</li>
</ul>
<p>LVM은 이 문제를 <strong>중간 계층</strong>을 하나 둠으로써 해결합니다.</p>
<pre><code><div class="code-block"><div class="code-header"><span class="code-title">plain</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-plain"><code class="hljs language-plain">디스크/파티션 → LVM → 파일시스템
</code></pre></div></code></pre>
<p>이 중간 계층 덕분에 디스크를 추가하거나, 용량을 늘리거나, 재배치하는 작업이 훨씬 유연해집니다.</p>
<hr>
<h2 id="lvm-주요-구성-요소" tabindex="-1" data-src-line="35">LVM 주요 구성 요소 <a class="header-anchor" href="#lvm-주요-구성-요소" aria-hidden="true">#</a></h2>
<h3 id="physical-volume-pv" tabindex="-1" data-src-line="37">Physical Volume (PV) <a class="header-anchor" href="#physical-volume-pv" aria-hidden="true">#</a></h3>
<p>Physical Volume은 <strong>물리 디스크 또는 파티션을 LVM에서 사용할 수 있도록 초기화한 단위</strong>입니다.</p>
<ul>
<li><code>/dev/sda</code>, <code>/dev/sdb1</code> 같은 실제 블록 디바이스가 대상입니다.</li>
<li><code>pvcreate</code> 명령으로 생성합니다.</li>
<li>이 단계에서부터 디스크는 LVM의 관리 영역으로 들어옵니다.</li>
</ul>
<p>PV는 아직 용량을 사용하는 단계는 아닙니다.<br>
말 그대로 “재료 준비” 단계에 가깝습니다.</p>
<hr>
<h3 id="physical-extent-pe" tabindex="-1" data-src-line="50">Physical Extent (PE) <a class="header-anchor" href="#physical-extent-pe" aria-hidden="true">#</a></h3>
<p>Physical Extent는 Physical Volume 내부를 나눈 <strong>최소 관리 단위</strong>입니다.</p>
<ul>
<li>기본 크기는 보통 4MB입니다.</li>
<li>LVM은 디스크를 연속 공간으로 다루지 않습니다.</li>
<li>항상 PE 단위로 나누어 관리합니다.</li>
</ul>
<p>PE 크기는 VG 생성 시 변경할 수 있으며,<br>
일반적으로 2의 거듭제곱 단위(2MB, 4MB, 8MB 등)를 사용합니다.</p>
<p>이 개념이 이후 용량 확장과 이동을 가능하게 만드는 핵심입니다.</p>
<hr>
<h3 id="volume-group-vg" tabindex="-1" data-src-line="65">Volume Group (VG) <a class="header-anchor" href="#volume-group-vg" aria-hidden="true">#</a></h3>
<p>Volume Group은 <strong>여러 개의 Physical Volume을 하나로 묶은 논리적인 저장소 풀</strong>입니다.</p>
<ul>
<li>하나 이상의 PV로 구성됩니다.</li>
<li>Logical Volume은 반드시 VG 안에서 생성됩니다.</li>
<li>실제 디스크 크기와 관계없이 하나의 큰 저장소처럼 보입니다.</li>
</ul>
<p>운영 관점에서는<br>
“이 서버에서 LVM으로 관리되는 전체 저장 공간” 정도로 이해해도 무리가 없습니다.</p>
<hr>
<h3 id="logical-volume-lv" tabindex="-1" data-src-line="78">Logical Volume (LV) <a class="header-anchor" href="#logical-volume-lv" aria-hidden="true">#</a></h3>
<p>Logical Volume은 <strong>사용자가 실제로 사용하는 디스크</strong>입니다.</p>
<ul>
<li>일반적인 파티션과 거의 동일한 역할을 합니다.</li>
<li><code>/dev/vgname/lvname</code> 형태로 접근합니다.</li>
<li>파일시스템을 생성하고 마운트하여 사용합니다.</li>
</ul>
<p>LVM의 장점은 바로 이 LV를</p>
<ul>
<li>확장</li>
<li>축소</li>
<li>이동</li>
</ul>
<p>할 수 있다는 점입니다.</p>
<hr>
<h3 id="logical-extent-le" tabindex="-1" data-src-line="96">Logical Extent (LE) <a class="header-anchor" href="#logical-extent-le" aria-hidden="true">#</a></h3>
<p>Logical Extent는 Logical Volume을 구성하는 최소 단위입니다.</p>
<ul>
<li>Physical Extent와 1:1로 매핑됩니다.</li>
<li>LVM은 <strong>PE ↔ LE 매핑 테이블</strong>을 관리합니다.</li>
</ul>
<p>이 매핑 구조 덕분에<br>
디스크 공간이 물리적으로 연속되지 않아도<br>
논리적으로는 하나의 볼륨처럼 사용할 수 있습니다.</p>
<hr>
<h3 id="filesystem" tabindex="-1" data-src-line="109">Filesystem <a class="header-anchor" href="#filesystem" aria-hidden="true">#</a></h3>
<p>Filesystem은 Logical Volume 위에 생성됩니다.</p>
<ul>
<li><code>ext4</code>, <code>xfs</code> 등이 대표적입니다.</li>
<li>파일시스템 생성 이후 마운트하여 실제 데이터를 저장합니다.</li>
</ul>
<p>중요한 점은,<br>
LVM과 파일시스템은 서로 다른 계층이라는 점입니다.</p>
<p>LVM에서 용량을 늘렸다고 해서<br>
파일시스템이 자동으로 커지지는 않습니다.<br>
이 차이는 실습 단계에서 반드시 짚고 넘어가야 합니다.</p>
<hr>
<h2 id="extent-개념-정리" tabindex="-1" data-src-line="125">Extent 개념 정리 <a class="header-anchor" href="#extent-개념-정리" aria-hidden="true">#</a></h2>
<p>Extent는 LVM에서 <strong>용량을 관리하고 할당하는 최소 단위</strong>입니다.</p>
<p>디스크 공간을 연속 영역으로 다루지 않고,<br>
고정 크기의 블록(Extent)으로 나누어 관리함으로써</p>
<ul>
<li>용량 확장</li>
<li>축소</li>
<li>이동</li>
</ul>
<p>같은 작업을 유연하게 처리할 수 있습니다.</p>
<p>이 개념을 이해하지 못하면<br>
LVM은 단순한 “디스크 묶기 도구”로만 보이게 됩니다.</p>
<hr>
<h2 id="실습-환경-초기화" tabindex="-1" data-src-line="143">실습 환경 초기화 <a class="header-anchor" href="#실습-환경-초기화" aria-hidden="true">#</a></h2>
<p>실습을 위해 기존 디스크의 메타데이터를 초기화합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash"><span class="hljs-comment"># 디스크 헤더 초기화 (주의)</span>
<span class="hljs-built_in">dd</span> <span class="hljs-keyword">if</span>=/dev/zero of=/dev/sda bs=512 count=1
<span class="hljs-built_in">dd</span> <span class="hljs-keyword">if</span>=/dev/zero of=/dev/sdb bs=512 count=1
<span class="hljs-built_in">dd</span> <span class="hljs-keyword">if</span>=/dev/zero of=/dev/sdc bs=512 count=1
</code></pre></div></code></pre>
<p>이 작업은 실제 운영 환경에서는 절대 사용하면 안 됩니다.<br>
순수 실습 환경에서만 의미가 있습니다.</p>
<hr>
<h2 id="physical-volume-확인과-생성" tabindex="-1" data-src-line="159">Physical Volume 확인과 생성 <a class="header-anchor" href="#physical-volume-확인과-생성" aria-hidden="true">#</a></h2>
<h3 id="pvs-명령어" tabindex="-1" data-src-line="161">pvs 명령어 <a class="header-anchor" href="#pvs-명령어" aria-hidden="true">#</a></h3>
<p><code>pvs</code>는 시스템에 존재하는 Physical Volume을 확인하는 명령어입니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">pvs
</code></pre></div></code></pre>
<p>아직 <code>pvcreate</code>를 하지 않은 디스크는 목록에 나타나지 않습니다.</p>
<hr>
<h3 id="pvcreate" tabindex="-1" data-src-line="173">pvcreate <a class="header-anchor" href="#pvcreate" aria-hidden="true">#</a></h3>
<p>디스크를 Physical Volume으로 초기화합니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">pvcreate /dev/sda /dev/sdb
</code></pre></div></code></pre>
<p>이제 <code>pvs</code>로 확인하면 LVM 관리 대상으로 편입된 것을 볼 수 있습니다.</p>
<hr>
<h3 id="pvdisplay" tabindex="-1" data-src-line="185">pvdisplay <a class="header-anchor" href="#pvdisplay" aria-hidden="true">#</a></h3>
<p><code>pvdisplay</code>는 특정 PV의 상세 정보를 보여줍니다.</p>
<p>이 단계에서는 VG에 속하지 않았기 때문에<br>
PE 크기와 할당 정보가 아직 비어 있는 상태입니다.</p>
<hr>
<h2 id="volume-group-생성" tabindex="-1" data-src-line="194">Volume Group 생성 <a class="header-anchor" href="#volume-group-생성" aria-hidden="true">#</a></h2>
<h3 id="vgcreate" tabindex="-1" data-src-line="196">vgcreate <a class="header-anchor" href="#vgcreate" aria-hidden="true">#</a></h3>
<p>두 개의 Physical Volume을 하나의 Volume Group으로 묶습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">vgcreate testvg /dev/sda /dev/sdb
</code></pre></div></code></pre>
<p>이 순간부터 두 디스크는<br>
논리적으로 하나의 저장소 풀처럼 동작합니다.</p>
<hr>
<h3 id="vgdisplay" tabindex="-1" data-src-line="209">vgdisplay <a class="header-anchor" href="#vgdisplay" aria-hidden="true">#</a></h3>
<p><code>vgdisplay</code>를 통해 VG의 전체 크기와 PE 정보를 확인할 수 있습니다.</p>
<p>여기서 중요한 포인트는 다음입니다.</p>
<ul>
<li>PE Size</li>
<li>Total PE</li>
<li>Free PE</li>
</ul>
<p>이 값들이 이후 LV 크기 계산의 기준이 됩니다.</p>
<hr>
<h2 id="volume-group-삭제" tabindex="-1" data-src-line="223">Volume Group 삭제 <a class="header-anchor" href="#volume-group-삭제" aria-hidden="true">#</a></h2>
<p>실습이 끝났다면 VG를 제거할 수 있습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">vgremove testvg
</code></pre></div></code></pre>
<p>VG를 제거하면 그 안에 속한 LV도 함께 제거됩니다.</p>
<hr>
<h2 id="logical-volume-생성" tabindex="-1" data-src-line="235">Logical Volume 생성 <a class="header-anchor" href="#logical-volume-생성" aria-hidden="true">#</a></h2>
<h3 id="lvcreate-기본-개념" tabindex="-1" data-src-line="237">lvcreate 기본 개념 <a class="header-anchor" href="#lvcreate-기본-개념" aria-hidden="true">#</a></h3>
<p>Logical Volume은 두 가지 방식으로 생성할 수 있습니다.</p>
<ul>
<li><strong>용량 기준 (-L)</strong></li>
<li><strong>Extent 개수 기준 (-l)</strong></li>
</ul>
<p>이 차이를 이해하는 것이 매우 중요합니다.</p>
<hr>
<h3 id="용량-기준-생성--l" tabindex="-1" data-src-line="248">용량 기준 생성 (-L) <a class="header-anchor" href="#용량-기준-생성--l" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">lvcreate -L 310M -n lvred vgcolor
</code></pre></div></code></pre>
<p>LVM은 항상 PE 단위로 동작하기 때문에,<br>
요청한 크기가 PE 단위에 맞지 않으면 자동으로 올림 처리됩니다.</p>
<hr>
<h3 id="extent-기준-생성--l" tabindex="-1" data-src-line="259">Extent 기준 생성 (-l) <a class="header-anchor" href="#extent-기준-생성--l" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">lvcreate -l 30 -n lvblue vgcolor
</code></pre></div></code></pre>
<p>이 방식은 PE 단위로 정확한 제어가 필요할 때 유용합니다.</p>
<hr>
<h3 id="남은-공간-비율로-생성" tabindex="-1" data-src-line="269">남은 공간 비율로 생성 <a class="header-anchor" href="#남은-공간-비율로-생성" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">lvcreate -l 50%FREE vgcolor
</code></pre></div></code></pre>
<p>VG에 남아 있는 공간의 비율을 기준으로 LV를 생성할 수도 있습니다.</p>
<p>운영 환경에서 자주 사용되는 방식입니다.</p>
<hr>
<h2 id="파일시스템-생성과-마운트" tabindex="-1" data-src-line="281">파일시스템 생성과 마운트 <a class="header-anchor" href="#파일시스템-생성과-마운트" aria-hidden="true">#</a></h2>
<p>Logical Volume 위에 파일시스템을 생성해야 실제로 사용할 수 있습니다.</p>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">mkfs.xfs /dev/vgcolor/lvred
mkfs.ext4 /dev/vgcolor/lvblue
</code></pre></div></code></pre>
<p>그 이후에 마운트하여 사용합니다.</p>
<p>이 단계에서야 비로소 사용 가능한 스토리지가 됩니다.</p>
<hr>
<h2 id="advanced-lvm-raid-볼륨" tabindex="-1" data-src-line="296">Advanced LVM: RAID 볼륨 <a class="header-anchor" href="#advanced-lvm-raid-볼륨" aria-hidden="true">#</a></h2>
<p>LVM은 단순히 디스크를 묶는 기능만 제공하는 것이 아닙니다.</p>
<p>소프트웨어 RAID 기능도 함께 제공합니다.</p>
<hr>
<h3 id="raid-1" tabindex="-1" data-src-line="304">RAID 1 <a class="header-anchor" href="#raid-1" aria-hidden="true">#</a></h3>
<ul>
<li>미러링 방식</li>
<li>데이터가 두 디스크에 동일하게 저장됩니다.</li>
<li>안정성이 가장 높습니다.</li>
</ul>
<hr>
<h3 id="raid-5" tabindex="-1" data-src-line="312">RAID 5 <a class="header-anchor" href="#raid-5" aria-hidden="true">#</a></h3>
<ul>
<li>패리티 분산 저장</li>
<li>디스크 하나까지 장애 복구 가능</li>
<li>읽기 성능이 좋습니다.</li>
</ul>
<p>단, 두 개 이상의 디스크가 동시에 장애가 나면 데이터가 유실됩니다.</p>
<hr>
<h3 id="raid-10" tabindex="-1" data-src-line="322">RAID 10 <a class="header-anchor" href="#raid-10" aria-hidden="true">#</a></h3>
<ul>
<li>RAID 1 + RAID 0 구조</li>
<li>성능과 안정성을 모두 확보</li>
<li>디스크 비용이 큽니다.</li>
</ul>
<hr>
<h3 id="lvm-raid-실습-예시" tabindex="-1" data-src-line="330">LVM RAID 실습 예시 <a class="header-anchor" href="#lvm-raid-실습-예시" aria-hidden="true">#</a></h3>
<pre><code class="language-bash"><div class="code-block"><div class="code-header"><span class="code-title">bash</span><button type="button" class="copy-button" aria-label="Copy code block">Copy</button></div><pre class="language-bash"><code class="hljs language-bash">vgcreate last /dev/sda /dev/sdb /dev/sdc
